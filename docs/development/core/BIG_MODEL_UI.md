# BIG-Model風UI

[資料別の確認範囲と原典との差](BIG_MODEL_REFERENCE.md)を参照。端末入力と画面は独立アダプター `big-model` が所有する。利用者のコマンド一覧は[統合マニュアル](../../manual/personal-settings.md#big-model-ui)。

- セッションの一般端末処理、エディタ、認証、ACL、メール、保管庫、Doorを共用する。BIG-Modelの表示、SIG選択、探索位置、電報入力・宛先、ページ停止は接続ごとの状態。
- SIGには既存のボード階層を使う。SIG一覧の表示番号はそのページのボードIDに紐付ける。記事一覧では永続記事IDを最低5桁で表示し、そのまま指定に使う。
- Article Coreの可視性、返信を含む番号順のページ、検索・新着フィルターを利用する。記事メタデータに日時・投稿者を含め、本文を読む権限と既読登録は従来のCoreで再検査する。
- 記事の本文・返信・閲覧状態は既存形式に保存する。個人探索表だけを既存SQLite設定の `big_model_scanlist` に保存する。整合バックアップ、論理エクスポート・復元の対象に含める。古い管理ツールがこの表を認識しないため、最新版と対になる管理ツールを使う。
- 探索の既定は前回ログイン時刻。認証結果を受け取る時点で現在のログイン記録を書き込む前の値を保持する。接続履歴を無効化している場合や前回時刻が得られない場合は、共通記事チェックポイントを使う。局時刻の日付指定は接続中の検索窓だけを変更する。
- 電報は送信先を表示した時点の接続IDとChat Coreの登録世代を照合する。受信拒否やミュートは一覧表示時と配信直前の双方で確認する。Chat Coreの私信を使用し、公開チャットログとメールへ保存しない。
- `U 9` の ON/OFF は既存の個別トーク受信設定を変える。表示上の「全員」「会員のみ」の区別は提供しない。送信には認証が必要。21文字はUTF-8符号位置の個数。
- 旧通信ソフト用の自動巡回応答、BigMAPのバイト互換、PC-98の画面制御やShift_JIS端末の互換は未確認。原作のSIGOP設定ファイル、アンケート、自動ダウンロード、データベース、専用質問コーナー、ハムレットは未実装。ファイルバッチ、共通管理、Door、会議はLiner Notesとして提供する。

## 検証入口

`make test-big-model` は分離したTelnet待受、構造化SQLite、テスト用保管庫、公開範囲を制限したボードを使う。フラット一覧とMMM・MASH表示、入れ子返信、検索、メール、電報、Door、探索表の再起動復元を検証する。WebコネクタとSSHの既存実接続試験でもBIG-Modelを通す。Core試験では同じ接続番号を再登録した場合の誤配を拒否し、探索表の原子置換とUI間の独立を確認する。
