# 一行会議のCoreとUI

## 原典と今回の仕様

- *mmm Revision 4.0 ユーザーマニュアル*「ライン会議」は、部屋ごとに一行ずつ記録し、数字で入室する方式を説明しています。`talk -n` は部屋一覧を省略して、参加登録済みの部屋の新着を巡回します。リアルタイムの `chat` は独立した機能です。[原典の公開先](https://webmid.kinet.ne.jp/mid/manual/wtsbbs/manual/MASHMAN/USER-utf8.txt)
- *MASH Commands Reference* §4.6 にも `talk -n` と参加登録済みの部屋を巡回する `new` が記載されています。MASHの書式拡張やパーソナルファイルへのリダイレクトは別仕様です。[MASHコマンドリファレンス](https://webmid.kinet.ne.jp/mid/manual/wtsbbs/manual/MASHMAN/COMMANDS-utf8.txt) / [運用例](https://webmid.kinet.ne.jp/mid/manual/wtsbbs/)
- Liner Notesの部屋は会員共用です。全員が部屋1を利用でき、管理者は部屋を追加できます。旧版の参加登録・座席・同時入室排他・Close/Lock/CUG・Knock・発言取り消しは今回の互換対象外です。`talk -n` は入れる全室を発言ID順に巡回します。
- 原典から未読位置を永続化する正確な時点は確認できませんでした。この実装では表示と既読更新を分けます。MMMは送信キューが空になった後に既読の確認を案内し、利用者が `a`（入室中は `/a`）を入力するまで既読位置を保存しません。RTBBSは `LINECONF SEEN 部屋 発言番号` で明示更新します。書き込みや一覧表示だけでも既読位置は変わりません。

## 責務と信頼境界

`conference_run` は部屋一覧、履歴、未読、投稿、位置取得、位置更新、部屋作成を受け付ける型付きAPIです。MMMとRTBBSの入力・表示は各アダプターが担当します。

ボードワーカーがデータを書き込みます。要求の会員IDと世代は認証済みの `SessionCore` が付与します。ワーカーは現在の接続枠・接続世代・会員ID・認証世代の組と会員の現行状態を照合します。割り当てが変わる前に受理して実行を始めた操作が確定する場合があります。その応答は接続枠を引き継いだ新しい接続へ転送されません。ゲストとログイン名 `guest` の会員は読み書きとも拒否します。今後の専用ゲスト種別は認証境界の同じ判定に追加できます。

チャットからは既存のUTF-8・制御文字・入力長の検査を利用し、アカウント判定は共有のIdentityProviderを利用します。チャットの履歴・通知・個別配送経路に一行会議の発言を渡す処理はありません。新着は一覧・巡回を実行した接続で取得します。

## 保存

既存の機能設定用SQLite接続に `conference_rooms`、`conference_lines`、`conference_read` を追加します。設定DBを統合した構成では本体DB、ファイル構成では従来の機能設定DBに入ります。既存のスキーマ番号とジャーナルは維持します。新規の部屋1は `General` です。

発言IDは局内で単調増加します。発言には部屋・会員ID・投稿時の表示名・Unix時刻・本文を保存します。読み取りの連続カーソルは排他的です。既読位置の更新は当該会員だけを対象とし、一つのSQL文で対象室の既読位置を最大値へ進めます。古いセッションの低い既読更新で巻き戻りません。

論理バックアップ、旧形式の中間エクスポート、別コピーへの復元・移行に3テーブルを含めます。既読位置は複合外部キーで、同じ部屋の発言を参照します。部屋の削除と発言の自動消去は提供していません。

## 試験

`make test-conference-core test-conference` はSQLiteの権限・不正入力・書き込み失敗・既読位置と、実接続による双方のUI・Chat分離・再起動・バックアップ復元を検査します。既存の `make check` に含まれます。
