# NET-COCK風端末UI

[参照資料](NET_COCK_REFERENCE.md)に版、確認箇所、出典コミットを記録した。原作と互換実装からコードは流用していない。

## 状態とCoreの境界

`net-cock` は独立した SessionUiAdapter。選択、許可リスト、会員のUI希望、認証、秘密入力、転送とDoorの切替制御は既存基盤を使用する。七つの端末UIが既存の `SESSION_UI_MAX=8` に収まる。さらに上限を変更する場合は、`SessionUiConfig.allowed` のビット幅、許可リストの255バイト制限、初期化ループ、保存名の31バイト制限と状態配列を合わせて確認する。次のVS風UIでも、原典に対応する表示方式を独立して選べる。

記事一覧は共通の平面ページを使い、投稿と返信をID順に混在させる。選択中、最後に本文を読んだ記事、最大10件の返信元移動履歴を接続状態に分けて保持する。メタデータ取得時はArticle Coreでボードと可視性を検証し、本文・既読・閲覧イベントへ触れない。本文は読書の都度アクセス権を再検査し、表示の後で個別既読を更新する。返信、削除、ファイルの取得は確定時にも既存の認可を通る。IDと親子関係は共有のまま。NET-COCKでの一般会員の取り消しでは、返信のある記事をCoreで拒否する。監査、リンク起点、非表示の既存ルールは引き続き適用する。

`MODE MENU` と `MODE COMMAND` を会員別に `net_cock_mode`、NET-COCKの購読を `net_cock_subscriptions` に保存する。巡回位置は共通の会員設定で種別5を使用する。購読は最大64件。更新時は会員の状態と認証世代を検査し、読み出し時にもボードを再検査する。最後まで巡回したときだけ開始時刻まで位置を進める。中断時は時刻を更新しない。全UI共通の個別既読は本文を表示した記事だけを対象にする。SQLiteの既存features保存・バックアップ経路へ新テーブルを登録した。

メール、PDS、本文入力・下書き、転送、TOPIC、Doorは既存機能を利用する。バッチの完了状態は共通転送の個別完了通知で更新される。`BATCH O` の切断は成功と全対象の完了を確認した場合に限る。回線番号の個別送信は表示時の接続IDと接続世代を照合する。公開チャット、電報、TOPIC、一行会議は各自の保存とアクセス規則を維持する。

## 操作と互換性

操作一覧は[統合マニュアル](../../manual/personal-settings.md#net-cock-ui)を参照。

- 原作の固定ゲストIDや数値ネットワークIDは作成しない。ログイン必須のアダプターとして会員認証・登録ポリシーを適用する。ゲスト向け5分類は公開運営例で、Liner Notesでは未認証画面でID入力と入会申請を案内する。
- ボード階層をグループに対応させ、表示中のグループを文字または番号で選ぶ。ページごとに表示ラベルを割り当て、安定した直接指定にはボードIDまたはボード名を使う。ヘッダーは日時、題名、投稿者名、サイズと返信元IDを表示する。原作の会員番号、論理通番／総件数、閲覧・返信集計は表示しない。
- `BSET` は順次Y/N/Enter/Q、`BSET ID Y|N` は個別指定。購読板だけを `RALL` と `RNALL` で巡回する。原作の一括メール削除 `RNALL Y` と、巡回中のメール処理は未対応。`RNALL N` は記事の連続表示に対応し、メールの操作は `MREAD` を使う。
- `MCHECK` は共通の送信済み一覧。複数宛先、受信拒否による配達ブロック、旧式の配達状態は未対応。`MBSET NOTIFY` は通知設定。PDSの登録は既存転送で受け付ける説明入力を使い、独立した記事とファイルのペアは作成しない。
- `.L`、`.P`、`.C`、`.Q` を実装。`.S`／`.O` は一覧に載った相手の個別受信ミュート解除／設定。`.T`／`.B` の発言は共通チャットで通常表示する。回線ごとの双方送出制御と表示配置、室外の公開チャット通知、行の再描画は未対応。
- `ADMIN` から共通のボード／会員管理を利用できる。`BCHANGE`、`MAKEID`、`UDLIST` は共通管理操作に接続する。その他の旧管理コマンドすべてに同等の操作があるわけではない。スラッシュ連結、旧テンプレート読込、旧自動巡回ソフトとのバイト単位の互換は未対応。
- UTF-8による端末表示を使用する。実際の端末・接続方式が扱える文字コードはLiner Notes共通仕様に従う。

## 検証経路

`make test-net-cock` は省略と番号の単体試験、ローカルBBSのTelnetでの平面／HyperNotes相互運用、P/F、U/I、TOPIC、メール、PDS、Door、保存・再起動を検査する。ヘッダーの可視性と本文非取得はArticle Core単体試験、SSHからの切替・ヘッダー・本文は既存のSSH統合試験でも検査する。GitHub-hostedとmain限定ネイティブ検証がそれぞれの対象コミットを扱う。
