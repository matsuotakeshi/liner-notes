# 保管庫メニューとZMODEM組み込み（stage49）

最新のstage51では一括ダウンロード、説明編集・再公開、日付指定新着一覧を追加しています。操作と制限は[READMEのstage51](README.md#stage51-保管庫の一括送信登録後の管理新着一覧)を参照してください。以下は各機能を導入した段階の説明です。

RTBBS 5.3βbのFILESYS.PASの一覧・検索・U（アップロード）・D（ダウンロード）という操作の流れを参考に、Liner notesの保管庫メニューへZMODEMを接続しました。DOSの保存形式や全機能の互換ではありません。

## 利用者の操作

ログイン後、メインメニューの **E** または `VAULT` で保管庫へ入ります。

| 入力 | 動作 |
| --- | --- |
| `L` | ファイル一覧 |
| 番号 | ファイル名・サイズ・説明・登録者などの詳細 |
| `+` | 一覧・検索・カテゴリの次ページ |
| `S 検索語` | ファイル名・説明・カテゴリを検索 |
| `C` | カテゴリ一覧 |
| `I カテゴリ` | カテゴリによる絞り込み |
| `U [説明]` | 端末からZMODEMでアップロード |
| `D 番号` | 保管庫からZMODEMでダウンロード |
| `H` / `?` | ヘルプ |
| `0` / `EXIT` | BBSへ戻る |

通常画面から `ZUPLOAD [説明]` / `ZDOWNLOAD 番号 [保存名]` も使えます。ダウンロードは保管庫の元のファイル名を使い、必要なら保存名を指定できます。アップロードの説明とダウンロード保存名の指定は各80バイトまでです。説明は省略できます。

アップロードではUを入力して案内が出てから、端末ソフトのZMODEM送信でファイルを選びます。ダウンロードではDと番号を入力し、端末側でZMODEM受信を開始します。自動検出に対応する端末なら端末側の設定に従って開始します。

**端末の転送完了表示に続く「ファイル #番号 を公開しました」または「送信が完了しました」が成功確認です。** アップロードはZMODEM受信とSHA-256検証が終わってから保管庫へ公開します。途中のファイルは一覧に出ません。キャンセルは端末側のZMODEM中止操作を使います。

転送中は通常コマンド・文字編集・エコー・メール通知・個別トークの割り込みを停止します。終了時には残ったプロトコル入力を捨て、短い待機後に保管庫メニューへ戻ります。失敗時も成功とは表示しません。ダウンロード先に同名ファイルがあり端末がスキップした場合も、送信成功とは扱いません。

## FreeBSDでの準備

Python 3とlrzsz 0.13.1を外部コネクタとして使用します。C製BBS本体へlrzszをリンクしません。上流の取得先・固定ハッシュ・ライセンスについては[従来のZMODEM説明](ZMODEM.md)を参照してください。

新規環境では、未作成のディレクトリを指定してエンジンを用意します。

```sh
python3 scripts/build-lrzsz.py deps/verified
```

次に、runtimeを動かす一般ユーザーで設定用ランチャーを作成済みです。作成済みファイルは上書きしません。spoolはそのユーザーが所有する0700の専用ディレクトリにします。

```sh
python3 scripts/configure-zmodem.py \
  --receiver "$PWD/deps/verified/local/bin/lrz" \
  --sender "$PWD/deps/verified/local/bin/lsz" \
  --spool-root "$PWD/zmodem-spool" \
  --output "$PWD/zmodem-helper"
```

runtimeの既存起動コマンドへ `--zmodem-helper /絶対パス/zmodem-helper` を追加します。保管庫は従来どおり `--vault-dir` で指定し、初期化済みのものを使ってください。新しい保管庫を用意する場合のみ、未使用のパスに `./vaultctl init /新しい保管庫のパス` を実行します。

```sh
./runtime --telnet --menu \
  --vault-dir /保管庫の絶対パス \
  --zmodem-helper "$PWD/zmodem-helper" \
  2222 notes.dat members.dat
```

外部接続の待受アドレスや会員・ボード・管理者ファイルは、既存の運用設定を引き継いでください。`--zmodem-helper`を省略した場合も保管庫の一覧・検索や専用クライアント転送は使えますが、メニューのZMODEM送受信は利用不可と案内します。Windows版ではこの外部プロセス機能を有効にせず、FreeBSD/POSIX側で運用します。

daemon設定には次を追加します。これは設定例であり、この作業では既存サービスを切り替えていません。

```sh
liner_notes_vault_dir="/保管庫の絶対パス"
liner_notes_zmodem_helper="/home/takeshi/liner-notes-stage49-20261028/zmodem-helper"
```

stage49の実機配置では、そのディレクトリ内へエンジンを独立してビルドし、ランチャーを作成済みです。旧stage38のディレクトリを残すことを前提にはしません。

## 分離と保護

- 保管庫本体・会員ファイルを開くのは既存のC側の所有者だけです。ZMODEMコネクタは保管庫ディレクトリや会員ファイルを渡されません。
- runtimeは既存のログイン済み接続に紐づいた制御要求だけを受け付け、保管庫ワーカーへ渡します。追加ログインやパスワードの保存はありません。要求ごとに会員・認可状態を確認します。
- 制御用の内部チャネルとZMODEMのバイト列は分離しています。端末から内部APIへ直接文字列を送れる構成ではありません。
- `zmodem_host.c`が外部プロセスとバイト転送、Pythonのコネクタが受信後の公開・送信前の検証、既存のTransferBackendが保管庫操作を担当します。通信方式や将来の会員管理の交換箇所を分けています。
- Telnetは両方向のBINARY交渉成立を要求し、IACのエスケープをruntime側で処理します。交渉が失われたら転送を終了します。ZMODEMエンジンへTelnet制御列をそのまま渡しません。
- 同時転送はサーバー全体で4接続まで、1回1ファイル16MiBまでです。エンジンの制限時間は初期120秒（設定ツールの`--timeout`で変更）、転送処理全体にも10分の上限があります。
- 会員停止・認証失効・切断・サーバー終了時には関連プロセスを停止します。公開前・各保管庫操作時にも認可を確認し、ダウンロード中は定期的にファイルの公開状態を確認します。
- 一時受信場所は専用の0700ディレクトリです。パス、リンク、制御文字、不正名、サイズ超過、複数ファイルなどは公開前に拒否します。

## 失敗・回復

ZMODEM受信途中の失敗では公開しません。一時ファイルは片付けます。ただし公開APIを開始した後で応答を失い、結果が不明な場合は元ファイルと再開情報を残します。利用者には管理者へ確認するよう案内し、サーバーのログへ回復用の保存先を記録します。管理者はFILEAUDITと保存先を照合してください。回復の手順は[ZMODEM.md](ZMODEM.md)の公開結果不明時の説明に従います。

回復用データは勝手に削除しません。spoolの総使用量・残存する回復用ディレクトリは管理者が確認してください。4接続の上限は、障害後に保持する回復データの総容量まで制限するものではありません。

## 今回の範囲

RTBBSにあった複数ファイルの一括転送、転送途中からのZMODEM再開、X/YMODEM、ファイルボードごとの別権限などは含みません。今回は1ファイルの送受信と、既存の一覧・検索・カテゴリ・管理者操作を一つのメニューへまとめています。lrzszを相手とするTelnet実通信を検証し、個々のGUI端末やSSH経由のZMODEMは別途実利用確認が必要です。

既存の保存形式に変更はありません。ソースキット内の旧RTBBSは変更していません。
