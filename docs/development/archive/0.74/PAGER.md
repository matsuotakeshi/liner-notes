# 記事のページ送り — 第14段階

対話メニューで `PAGER ON` を入力すると、記事を画面の高さに合わせて分割表示します。初期状態はOFFです。接続直後はOFFですが、第15段階の [会員設定](PREFERENCES.md) を保存している場合、ログイン時に復元します。未保存の切替は接続ごとに独立します。

| 入力 | 動作 |
| --- | --- |
| `PAGER` | 現在のON/OFFを表示 |
| `PAGER ON` | 記事のページ送りを有効化 |
| `PAGER OFF` | ページ送りを無効化 |
| `PAGER SIZE 80 24` | 幅と高さを手動指定 |
| Enter | 表示途中の次ページへ |
| `Q` / `/CANCEL` | 表示途中の残りを破棄して操作画面へ |
| `OFF` / `PAGER OFF` | 表示途中の残りをまとめて表示し、以後のページ送りもOFFへ |

ページ待ち中のQは接続終了ではありません。その他の入力は掲示板コマンドとして実行せず、ページ操作の案内を再表示します。本文の表示が完了して通常のプロンプトに戻った後は、従来どおりコマンドを実行できます。表示を中止しても現在の記事選択は維持します。ページ送りや表示完了による自動既読化はしません。

## 画面サイズ

既定は80桁×24行です。TelnetのNAWSで通知された幅・高さを利用し、表示途中の変更も次ページから反映します。手動指定の範囲は幅20〜240、高さ5〜100です。範囲外や0のTelnet通知は、該当する寸法を既定値へ戻します。手動指定後にNAWSの値が変われば、その通知値が適用されます。

ページあたりの本文表示には高さから3行を引いた行数を使い、案内・入力の領域を残します。記事の見出しや操作案内も同じ表示単位に含みます。長い行は幅より1桁手前で明示的に折り返し、UTF-8の途中で分断しません。一般的な日本語の全角文字は2桁、ASCIIは1桁として数えます。結合文字・絵文字・曖昧幅文字の描画は端末によって異なり、すべての端末での桁一致は保証しません。

対象は題名・本文を含む記事表示です。READ、記事番号選択、親子・兄弟移動、次の未読、管理者のINSPECTなど、共通の記事応答を表示する経路に適用されます。第16段階では [一覧の画面ページ送り](LIST_PAGER.md) にも対応しました。従来の件数単位の取得を維持し、その表示を画面サイズでさらに分割します。raw応答はPAGER ONでも分割しません。

## 実装とCOM・Web

ページ送りはSessionの表示処理に置き、記事保存処理や通信プロトコルから分離しています。将来のCOMアダプターは `session_dimensions(session, columns, rows)` で設定値を渡せます。Webではページ送りをOFFにするかrawの応答を使用できます。TelnetアダプターはNAWSの変化をこのAPIに渡します。

1接続につき最大8192バイトの表示用領域を確保します。ページ待ち中も他接続を処理します。接続破棄や会員の接続失効では残りの本文も消去します。表示中の本文は閲覧要求が許可された時点のコピーであり、途中で記事を非表示にしても既に取得した表示内容は撤回しません。
