# 会員間メール（stage48）

RTBBS 5.3βbのMAILSYS.PASにある、会員宛メール、送受信両者による閲覧、受信者による既読化、受信メールへの返信、確認付き削除を参考にしたC実装です。旧DOSの保存形式・全コマンドとの完全互換ではありません。

## 操作

BBSから `MAIL` で専用画面に入ります。

| 操作 | 内容 |
| --- | --- |
| `L` / `LIST` | 自分が送受信したメールの一覧 |
| `N` / `NEXT` | 次の未読受信メールを開く |
| `T` / `LATEST` | 最新の送受信メールを開く |
| 番号 / `READ 番号` | メールを読む |
| `E` / `SEND` | 宛先ログイン名・題名を入力して本文を作成 |
| `R 番号` / `REPLY 番号` | 受信メールの送信者へ返信。題名は元メールを引き継ぐ |
| `K 番号` / `DELETE 番号` | 削除確認。Yで確定、それ以外は中止 |
| `SENT` / `INBOX` / `UNREAD` | 送信・受信・未読に一覧を絞る |
| `+` | 一覧の続き（1ページ8件。末尾の後は先頭へ） |
| `H` / `?` | ヘルプ |
| `0` / `EXIT` | BBSへ戻る |

`MAIL SEND bob 題名`、`MAIL READ 1`、`MAIL REPLY 1`、`MAIL DELETE 1` の直接指定も使えます。返信は受信者から元の送信者へ行います。`REPLY 番号 新しい題名` で返信の題名を指定できます。`R` / `K` 単独なら最後に選択したメールを対象にします。

本文は1行ずつ入力し、単独の `.` で保存・送信します。`/CANCEL` は中止、`/PREVIEW` や行編集・Undoも使用できます。メール下書きの `/SAVE` は保存して編集を終了します（下記）。題名80バイト、本文16384バイト（stage53以降）、最大10,000通（削除済みを含む）です。本文検索はstage52、停止中の別ファイル整理による容量削減はstage53で追加しました。添付ファイル・日付指定巡回は未実装です。

送信者と受信者だけが一覧・本文を読めます。管理者権限による閲覧は追加していません。受信者が本文を開くと既読になり、送信者が開いても既読にはなりません。ログイン時には未読件数を日英で案内します。送信先がオフラインでも保存できます。未登録・利用停止中の宛先へは送れません。

RTBBSの削除動作に合わせ、当事者のどちらかが削除すると両者から見えなくなります。各人の一覧だけから隠す方式ではありません。削除済みの元メールに対して、入力中の返信を後から送信することも拒否します。削除は論理削除であり、保存ファイル内の本文を物理消去する機能ではありません。

## 保存と構成

会員ファイルが `members.dat` ならメールは `members.dat.mail` に保存します。掲示板の記事・検索・操作履歴とは分離します。会員情報と一緒に停止中にバックアップしてください。新規メール・既読・削除は検査値付きの記録として追記し、同期保存が成功してから応答します。不正・途中で切れた記録は起動時に拒否し、勝手に初期化しません。

会員認証と宛先解決は既存ワーカーで行い、メール保存は `mailbox.c`、操作画面は `session.c` で管理します。パスワード、個別トークの本文、一般ボードの内容はメールファイルに混ぜません。

既存データを変換せず、新しいメールファイルを追加します。旧runtimeはメールファイルを扱わないため、戻した場合は新機能を利用できません。stage42・43で追加済みの会員設定・管理履歴の旧版互換制限は引き続き適用します。

## stage45: メール下書きの保存・再開

会員ごとにメール下書きを1件保存できます。記事の下書きとは別枠で、宛先・返信元・題名・本文を保存します。本文が空でも保存でき、再ログイン・サーバー再起動後も再開できます。宛先と題名の入力を終え、本文編集に入ってから使用してください。

| 操作 | 内容 |
| --- | --- |
| 本文編集中の `/SAVE` | 下書きを保存し、メール画面に戻る |
| `MAIL DRAFT` | 自分の保存下書きの版番号・宛先・返信元・題名を確認 |
| `MAIL RESUME` | 保存下書きから本文編集を再開 |
| `MAIL DRAFT DELETE 版番号` | 指定した版の保存下書きを削除 |

メール画面内では `DRAFT` / `RESUME` / `DRAFT DELETE 版番号` も使えます。編集中の `/HELP` はメールの説明を表示します。

`/CANCEL`や切断は未保存の編集を破棄します。以前に保存した下書きは残ります。自動保存ではありません。再開した下書きから送信すると、送信と下書き削除を1つの記録で保存します。送信失敗時には保存下書きを削除しません。

別接続で保存・削除された古い版からの上書きや送信は拒否し、編集内容をその接続に残します。保存下書きがある状態で別の新規メールを作った場合も、`/SAVE`で既存下書きを上書きしません。`MAIL DRAFT`で確認し、必要なら既存下書きを再開または版番号指定で削除してください。保存せず新規メールを直接送信しても、別に保存していた下書きは残ります。

返信元が削除された場合や宛先が利用停止になった場合、再開を拒否します。下書き自体は残り、`MAIL DRAFT`で確認・削除できます。本文は送信前には宛先へ公開されません。

保存先は既存の `members.dat.mail` です。**更新前に停止中の会員ファイルとメールファイルをバックアップしてください。** stage44のメールをそのまま読み込めますが、下書きの新しい記録を含むメールファイルはstage44では読めません。旧版へ戻す場合は更新前のバックアップが必要です。

試作配置先: `/home/takeshi/liner-notes-stage45-20261028`。既存サービスの切り替えは行いません。

stage45はFreeBSD 15.1とWindowsで関連9本のPython試験が成功しました。FreeBSDではチャット本体のC試験も成功。最終ヘルプ修正後に両OSで下書き・ヘルプ試験を再実行し、117ファイルのハッシュを照合しました。空本文の保存、再起動、記事下書きとの分離、同時接続の競合拒否、送信と下書き削除、返信元削除、日英Telnet画面を確認。FreeBSDでは短い書き込みによる保存失敗と不完全な記録の起動拒否も確認しています。記録は `evidence/freebsd-stage45.txt` と `evidence/windows-stage45.txt` です。

## stage46: ログイン時のメール下書き案内

メニュー表示を使う接続では、ログイン成功時に保存中のメール下書きの版番号と `MAIL RESUME`・`MAIL DRAFT` の案内を1回表示します。会員が保存した表示言語を優先し、日本語・英語に対応します。記事下書きの案内、記事の未読件数、メールの未読件数も従来どおり表示します。

案内は本人だけに表示し、宛先・題名・本文は含めません。自動で編集画面に移らず、保存データにも書き込みません。通常のコマンドごとには再表示しません。未保存・送信済み・削除済みの下書き、ログイン失敗時には表示しません。メニューを使わないraw接続の応答形式は維持します。

宛先の利用停止や返信元の削除によって再開できなくなった下書きも、保存されている間は案内の対象です。`MAIL DRAFT`で確認し、必要に応じて版番号を指定して削除してください。

今回の変更で保存形式の追加変更はありません。stage45のデータをそのまま使えます。配置先は `/home/takeshi/liner-notes-stage46-20261028`。既存サービスの切り替えは行いません。

stage46はFreeBSD 15.1・Windowsで関連6本のPython試験が成功しました。本人限定の案内、保存言語の復元、日英メニュー・Telnet、記事下書き／未読案内との併存、ログイン失敗時の非表示、raw接続との互換、表示前後の保存ファイル一致、送信・削除後の非表示を確認しました。検証機との118ファイルのハッシュも一致しています。記録は `evidence/freebsd-stage46.txt` と `evidence/windows-stage46.txt` です。

## stage47: ログイン中のメール新着通知

メニュー表示を使うログイン済みの受信者へ、メールの保存成功後に「新着メールがN件届きました。MAILで確認できます」と通知します。英語表示にも対応します。同じ会員の複数接続にはそれぞれ通知し、宛先以外の会員やゲストには表示しません。送信者・題名・本文は通知に含めません。送信失敗・下書き保存では通知しません。

本文編集、パスワード入力、バイナリ転送、ページ送り待ち、宛先・題名入力、削除確認、処理待ち、待機、連続読み出し、チャット・個別トーク中は通知を保留し、通常のBBS／メール画面に戻ってからまとめて知らせます。通常プロンプトで入力途中の場合は、通知後に入力途中の文字を再表示し、コマンドの内容を保ちます。

件数はその接続が保留していた到着通知の数で、現在の未読件数ではありません。別接続で既読・削除にしたメールの到着も含む場合があります。読むには`MAIL`を使ってください。通知自体は既読にしません。

通知待ちの件数は接続中だけ保持し、ログアウト・認証切替・接続終了時に破棄します。オフラインや再接続後は従来のログイン時未読件数で確認できます。メニューを使わないraw接続には非同期通知を追加しません。保存形式の変更はありません。

配置先: `/home/takeshi/liner-notes-stage47-20261028`。既存サービスの切り替えは行いません。

stage47はFreeBSD 15.1・Windowsで関連8本のPython試験と入出力アダプタのC試験が成功しました。実接続で複数接続の宛先限定通知、入力途中の復元、編集・パスワード入力中の保留と集約、日英表示、送信失敗・ログアウト後・raw接続の非通知を確認しました。C試験でバイナリ転送・ページ送り・処理待ち・チャット中の保留と認証失効時の破棄も確認。119ファイルのハッシュが検証機と一致しています。記録は `evidence/freebsd-stage47.txt` と `evidence/windows-stage47.txt` です。

## stage48: 会員ごとの新着通知ON/OFF

| 操作 | 内容 |
| --- | --- |
| `MAIL NOTIFY` | 自分の現在の設定を確認 |
| `MAIL NOTIFY ON` | ログイン中の新着メール通知を有効にする |
| `MAIL NOTIFY OFF` | ログイン中の新着メール通知を無効にする |

メール画面内では `NOTIFY` / `NOTIFY ON` / `NOTIFY OFF` も使えます。初期値はONで、既存会員も設定を変更するまで従来どおり通知を受けます。設定は変更時に自動保存され、再ログイン・再起動後にも復元します。`PREFS SAVE`は不要です。確認・同じ値への変更では記録を追加しません。

変更は同じ会員の別接続にも反映します。OFFにすると表示待ちの新着通知も取り消し、その後の到着通知を蓄積しません。ONへ戻してもOFF中のメールをまとめて通知せず、以降に届くメールを通知します。既に表示・送信キューに入った案内は取り消しません。

メールそのものの送受信・保存・未読状態には影響しません。ログイン時の未読件数と保存下書きの案内はOFFでも表示します。自分の通知設定だけを変更でき、管理者が他会員の設定を変更する入口は追加していません。日英表示とHELP MAILに対応しています。

設定は会員管理側で保存し、通知処理には設定値と版番号を渡します。保存成功後だけ接続へ反映し、古い版の設定で新しい状態を戻さないようにしています。会員ファイルに新しい設定記録を追加するため、**更新前に停止中の会員ファイルをバックアップしてください。** stage47の既存データはそのまま読めますが、新設定を保存した会員ファイルはstage47以前では読めません。旧版へ戻す場合は更新前のバックアップが必要です。

配置先: `/home/takeshi/liner-notes-stage48-20261028`。既存サービスの切り替えは行いません。

stage48はFreeBSD 15.1・Windowsで関連10本のPython試験と入出力のC試験が成功しました。初期ON、本人の設定変更・確認、変更の自動保存と再起動、同じ設定の追記抑制、複数接続への反映、保留通知取り消し、ON時の過去通知非再生、日英表示、言語・ページ送り・チャット設定との分離、不正値・途中記録の拒否を確認しました。FreeBSDでは短い書き込みによる保存失敗も確認。古い設定版の拒否と別会員への非反映はC試験でも検証しています。120ファイルのハッシュが一致しています。記録は `evidence/freebsd-stage48.txt` と `evidence/windows-stage48.txt` です。

## stage52: 題名・本文検索

`MAIL SEARCH 語句`で本人の送受信メールを部分一致検索します。大小文字を区別し、削除済みは除外します。`+`で続き、`MAIL SEARCHFROM カーソル 語句`で直接再開できます。検索条件は本文閲覧後も保持しますが、ログアウト時に消去します。検索は既読状態を変更せず、管理者にも他会員間メールの閲覧権限は与えません。
