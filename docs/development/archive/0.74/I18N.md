# 表示メッセージの多言語対応

日本語（ja）と英語（en）を用意しました。メニュー、入力プロンプト、一覧・記事の見出し、操作案内、保存・既読通知、エラーを接続ごとに切り替えます。記事本文・題名・ボード名・会員名はそのまま表示します。文字コードはUTF-8です。

## 操作

```text
LANG en
LANG ja
LANG
```

LANGだけで現在の言語と選択肢を表示します。未知の言語コードはエラーとなり、現在の言語を維持します。切替は通常のコマンド待ちで行えます。題名・本文・パスワードの入力中は、その入力内容として扱います。

言語を変えても、選択中のボード・記事・一覧の次ページ位置は変わりません。ログイン／ログアウト、RAW／MENUの切替でも同じ接続の言語を維持します。他の接続には影響しません。言語は会員データに保存せず、再接続時はサーバーの初期言語に戻ります。

```sh
# 初期言語は日本語
./runtime --menu 23230 notes.dat members.dat boards.example.conf
# 接続時から英語
./runtime --menu --lang en 23230 notes.dat members.dat boards.example.conf
```

`--lang` は `--menu` と順不同で、ポート番号より前に指定します。raw表示でもLANGで選んでからMENUに入れます。既存のrawプロトコル、内部応答コード、起動時の運用ログは英語のままです。コマンド名や操作キーも共通です。

## 開発時の追加方法

- `src/locales/ja.def` と `src/locales/en.def` に、安定したメッセージIDと文言を置きます。表示処理は日本語の文字列ではなくIDで参照します。
- カタログはビルド時に組み込むため、実行時の外部ライブラリやカタログファイルの配置は不要です。文言変更後は再ビルドしてください。
- 新しいメッセージは各カタログに同じIDで追加し、`ui_text()` で取得します。ワーカーのエラーを追加した場合は `ui.c` のエラーコード対応表にも追加します。
- 新しい言語は `src/locales/<code>.def` を作り、`messages.h` のLanguageと `messages.c` のカタログ・言語コード解決に登録します。英語カタログがメッセージIDの基準です。
- `%u`、`%s`、`%.*s` などは引数の型と順序を維持してください。文脈を持つ文全体を翻訳することを基本とします。printfの位置指定引数は現状使いません。
- 翻訳値が欠けた場合の実行時フォールバックは英語です。ただし通常の `make test` では不足・空欄・重複ID・書式不一致を失敗とし、翻訳漏れの出荷を防ぎます。

`tests/test_i18n.py` はカタログ検査に加え、実ソケットで日英同時接続、初期言語、言語切替後の記事・ページ位置、登録・投稿・返信・既読・権限エラー、入力データの保持、再接続を検証します。既存の日本語メニュー試験とrawコマンド試験も継続します。
