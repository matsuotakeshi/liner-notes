# 管理者によるチャット退出措置（stage43）

管理者がチャット室で `/KICK ログイン名` を入力すると、その会員のチャット中の接続（入室処理中を含む）へ通知し、接続を終了します。同じ会員が複数の接続で入室している場合はすべて対象です。

```text
/KICK bob
```

実行者には対象名と終了した接続数を表示します。管理者権限は従来の `--admins` 設定を使い、操作時に会員認証・停止状態・管理者権限を再確認します。自分自身や管理者として登録された会員は対象にできません。ログイン名の完全一致で指定し、ハンドルや接続番号は使いません。

## 退出後の扱い

- 掲示板を閲覧中、記事を編集中、ファイルを転送中の別接続は終了しません。
- 対象のチャット接続はBBSメニューへ戻さず、通知後に切断します。入力途中の文や処理待ちの入力を破棄し、BBS操作として誤実行しないようにします。
- 個別トークの相手には退出が通知され、後続の入力を共通チャットへ自動送信しません。
- 会員資格の停止ではありません。再接続・再入室は可能です。継続的な利用停止には既存の `SUSPEND` を使ってください。
- 保存済みの受信設定・ミュート、記事、プロフィールは変更しません。
- 通知は接続の出力キューへ送ります。すでに相手が切断している場合など、画面で読めたことまでは保証しません。

## 操作履歴

退出指示は既存の操作履歴へ `CHAT_KICK` として保存します。実行日時・操作者・対象会員IDが記録され、`AUDIT` と `AUDIT ACTOR ログイン名` で確認できます。記事操作ではないため記事別絞り込みには表示しません。日英ヘルプ・履歴表示に対応しています。

保存と同期が完了してから退出を適用します。保存できなかった場合は成功を表示せず、対象接続を終了しません。要求した管理者が途中で切断しても、保存済みの指示は適用します。

履歴は「退出指示」の記録です。保存中に対象が自分で退出する場合や、登録会員がチャット室にいない場合もあるため、切断完了や通知の既読証明ではありません。現在対象の接続がなければ終了数は0で、履歴は残ります。再起動時に過去の退出指示を再実行することはありません。
