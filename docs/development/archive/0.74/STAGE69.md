# Liner notes 0.69 / stage69

RTBBS 5.3βbのFILESYS、PROFSYS、MAINSYS、SYSOPCMD、EDITSYSの操作を参照した追加改修です。既存のデータ・ID・プロフィール公開設定を維持します。

## 対応内容

| 項目 | 変更 |
| --- | --- |
| 親SIGOP | 担当配下の新設・設定変更、下位SIGOPの任命。親変更は移動元と先の両方を確認。自己昇格・担当外の取り込みを拒否 |
| グループ | 現在の担当ボードの閲覧・投稿条件にあるグループの会員追加・除外。保護管理者は変更不可 |
| ファイル選択 | 番号で操作画面へ。表示・転送・バッチ追加・説明編集・削除を続けて操作 |
| 階層 | DIRの子一覧から番号選択、CD 子パス、0/CD ..で親へ。MENUノードは子一覧を表示 |
| バッチ | D送信・L一覧・C確認してクリア・M管理コピー。送信完了とコピー完了は別管理 |
| 個別完了・失敗 | 確認済みファイルだけDONE、未完了はPENDING。途中失敗でも成功分の取得履歴と回数を保持し、再送は未完了だけ |
| MATCH・ワイルドカード | 現在ボード内に限定。英字の大小を無視し、名前/拡張子を別々に比較。*.*は拡張子なし、?は末尾空白にも一致 |
| XMODEM | SUM・CRC・1Kを選択。送信時のSUM/CRCは受信側の要求による。1Kは1024バイトブロック |
| 管理コピー | FILECOPY / BATCH COPY。元・先の管理権限を確認。登録者・説明・日付・ASCIIを保持し、新規IDを発行 |
| 一覧・履歴 | 属性・取得回数・説明を一覧に追加。登録時PROTOCOLとその変更を記録。旧記録UNKNOWN、コピーCOPY |
| 自動ID | 接頭辞・数字桁数・最初のIDを設定可能。既存名・永久欠番は維持 |
| 入会申請 | 全入力を確認してYで確定、Eで再入力、/CANCELで中止してからパスワード入力 |
| プロフィール | 項目番号を選ぶ編集・検索。管理者は編集対象を選択。検索は公開可能な詳細を順次表示 |
| 個人情報・グループ検索・USERLOG | 下記の互換モードを追加。既定・既存公開範囲は維持 |
| 文書・誕生日 | welcome.txt / systemnews.txt / birthday.txtを追加。設定タイムゾーンの日付で本人へ誕生日表示 |
| エディタ | S3-10などの範囲検索、全一致強調・件数表示、MによるL/Sの行番号切替、接続者メモ |
| チャット・編集中 | Wは室外も含む接続者、#は時刻・接続時間・人数・本人利用集計。Tは一言送信後に元の画面へ復帰。/TALKの継続会話は維持 |

## 任意設定

rc.confまたはliner_notes.conf:

```sh
liner_notes_rtbbs_member_policy="NO"
liner_notes_id_mode="auto"
liner_notes_id_prefix="bbs"
liner_notes_id_digits="5"
# 空の会員台帳の最初だけ任意の名前にする場合:
# liner_notes_id_first="sysop"
liner_notes_login_text_dir="/usr/local/share/liner-notes"
```

`liner_notes_rtbbs_member_policy="YES"`は、本人による住所・誕生日変更を管理者限定とし、GROUP検索をSIGOP/管理者、実名・カナ・住所・電話の項目検索を管理者限定にします。USERLOG/USERTABLEは登録会員へ公開します。**既存の非公開項目や誕生年非表示はそのまま**で、検索も公開範囲を守ります。NOなら従来の動作です。

直接起動では `--rtbbs-member-policy`、`--id-prefix`、`--id-digits`、`--id-first`、`--login-text-dir`を使用します。IDの既定は従来のu000001形式。IDは英小文字の既存ルールを維持し、`sysop`という名前だけで管理者権限を与えることはありません。管理者は従来どおりadminsファイルで指定します。

welcome.txtは接続直後のゲスト画面、systemnews.txtは接続時・ログイン成功時に表示。birthday.txtは本人の誕生日に表示し、空なら日英の標準挨拶を使います。各文書はUTF-8で4KiBまで、欠落・空を許容します。バナー、システム案内、終了文は従来のファイルを使います。

## 保持する差異と運用上の注意

- 全体会員レベル、ボード削除・記事移動、システム停止は全体管理者の範囲です。SIGOPにOSの権限は渡しません。
- 名前付きコマンドも利用可能です。旧DOSの画面位置や8.3のファイル名制限までは再現せず、UTF-8・長い名前を維持します。
- コピー先は新規ID・独立した取得回数となります。バッチ状態は接続限り、確定した取得履歴は永続保存です。
- 過去の取得履歴に、以前記録されなかった転送方式を推測して補完しません。登録方式UNKNOWNはその意味です。
- 新しいQ履歴とXMODEM方式名を古い実行ファイルで読むことはできません。戻す際は停止して、更新前のバックアップ一式から復元してください。
- 任意の文書を端末に表示するため、文書の中に秘密情報を置かないでください。個別トーク本文を共通チャットログへ保存しません。

検証結果は `evidence/stage69/` に記録します。既存稼働サービス・rc.conf・データをこの改修で切り替えることはありません。

## 検証記録

FreeBSD実機で既存機能22系列と追加機能の回帰試験を実施し、不一致箇所を修正して関連試験を再実行しています。portsは標準PREFIXと別PREFIX・DOCS無効の両構成でstage / check-plist / stage-qa / packageを検査しました。最終結果は配布バンドルのevidence/verification.jsonを参照してください。

XMODEM-1Kの実転送試験では一度、受信側が中断を返しました。詳細ログ付きの追加3回ではSUM・CRC・1Kの送受信と再起動後の取得回数保存がすべて通っています。中断の原因は特定できていないため、既知の確認事項として記録します。失敗を成功として扱う変更は行っていません。
