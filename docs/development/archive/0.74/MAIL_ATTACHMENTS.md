# メール添付ファイル（stage65）

メール1通に最大16ファイル、1ファイル最大1GiBを添付できます。公開保管庫とは別の非公開領域を使い、通常のメールと同じく送信者・受信者だけが取得できます。SYSOPに閲覧の例外はありません。受信者も送信前の下書き添付は読めません。

## 端末での操作

ZMODEMを使う場合は、従来のZMODEMヘルパー設定と対応端末が必要です。

`ZMAILUPLOADBATCH 説明` なら最大16個をまとめて受信できます。`MAILFILES` で番号を確認し、編集時に `/ATTACH 番号` を繰り返します。中断した一括受信は `ZMAILRESUMEBATCH 同じ説明` で再開します。

1. `ZMAILUPLOAD 説明` を実行し、端末からファイルを送ります。完了表示にメール用ファイル番号が出ます。
2. `MAIL SEND 相手 題名` でメールを作成します。
3. 本文編集中に `/ATTACH ファイル番号` で添付します。繰り返すと追加でき、`/DETACH 番号` は指定した添付を、`/DETACH` はすべての添付を外します。添付には自分がメール用にアップロードしたファイルを指定します。
4. 本文を入力し、`.` で送信。`/SAVE` なら添付番号も含めて下書き保存し、`MAIL RESUME` で再開できます。
5. 受信側は `MAIL READ メール番号` で表示された添付番号を指定して、`ZMAILDOWNLOAD 添付番号` で取得します。

ファイル番号とメール番号は別です。公開保管庫のファイル番号も別の番号空間です。添付だけを送る場合も本文を入力してください（空行1行でも可）。返信に元メールの添付は自動コピーしません。受信者が転送したい場合はダウンロードして、自分のメール用ファイルとして再アップロードしてください。

`MAIL FILES` は本人のメール用ファイル一覧です。受信途中と送信可能なファイルを表示し、8件ずつ `MAIL FILES 次番号` で続きます。受信した他人の添付は、この一覧ではなくメール本文の表示から取得してください。

不要なファイルは `MAIL DROP 添付番号 CONFIRM` で取り消し・容量回収できます。保存済み下書きや削除されていないメールから参照されている間は拒否します。送信・保存する前の編集中だけの添付指定は参照として保持しません。別接続で先に取り消した場合、保存・送信時にエラーになります。

## 専用転送クライアント

既存の転送クライアントに `--connector mail-line-v1` を指定します。公開保管庫用の状態ファイルとの混用を拒否します。

```sh
python3 scripts/vault-upload.py --connector mail-line-v1 --host HOST --port 2222 --user USER --state mail-upload.json file.zip
python3 scripts/vault-upload.py --connector mail-line-v1 --host HOST --port 2222 --user USER --state mail-upload.json --resume file.zip
python3 scripts/vault-download.py --connector mail-line-v1 --host HOST --port 2222 --user USER ATTACHMENT_ID output.zip
```

公開ボードの `--category` はメール添付には使いません。名前は既存スクリプトと共通ですが、コネクタが転送先を区別します。通常のクライアントの再開機能と、ZMODEM回線上の途中再開は別です。ZMODEM自体の途中再開には対応するヘルパーと受信側の再開設定が必要です。

ZMODEMで受信後の保存確認に失敗した場合、回復用ディレクトリと `upload.json` を残します。そこにもメール用コネクタの識別子を保存し、公開保管庫へ再開することを防ぎます。途中の予約は `--cancel` または本人の `MAIL DROP` で取り消せます。

## 保存・権限・削除

添付は会員ファイル名に `.mailfiles` を付けた専用ディレクトリに保存します。例: `members.dat.mailfiles/`。ファイル保管庫の公開先とは別です。過去の添付参照があるのに領域が失われた場合、番号の再利用による誤配を防ぐため自動で作り直さず、添付操作を拒否します。整合したバックアップ一式から復旧してください。`--disable vault` でもメール添付は動作し、`--disable mail` では添付の転送も拒否します。

- 添付は送信者が保存したバイト列で固定され、公開保管庫ファイルへのリンクではありません。
- 公開前のSHA-256確認、所有者確認、チャンクごとのアクセス確認を行います。認証の失効は既存の会員セッション制御に従います。
- 添付番号はメール本文と同じ保存レコードに含めます。メール送信失敗だけで添付が受信者へ公開されることはありません。
- メール削除、下書きの添付変更・削除後、最後の保存済み参照がなくなった添付を非公開化してから実体を削除します。同じ添付を複数のメールで使う場合、最後の参照がなくなるまで保持します。
- 現行メール削除は送受信者共通の削除です。自分の一覧からだけ消す操作ではありません。
- 削除途中に中断した場合や、その起動中に添付領域をまだ開いていない場合は、次に添付へアクセスする際に回収を実行・再試行します。回収に失敗した場合はサーバーログへ記録します。正常に隠した後は削除未完了の実体も取得できません。
- 一度も保存・送信していないアップロードは、自動的には捨てません。本人が `MAIL FILES` と `MAIL DROP` で整理できます。期限による自動削除はありません。

領域全体256MiB、累計ファイル番号2000、操作記録10000件が既定値です。stage63では領域内の `limits.conf` でそれぞれ設定でき、0で設定上の制限を解除できます（`STAGE63.md`）。受信途中は全体8件／会員2件です。容量回収してもIDは再利用しません。

## 更新・バックアップ・整理

更新前にサービスを停止して、会員・メール・添付ディレクトリを含むデータ一式をバックアップしてください。添付付きメール／下書きには新しい記録形式を使うため、stage54以前へ戻すときはバックアップ一式が必要です。既存の添付なしメールはそのまま読めます。

`notes_compact.py mail` は添付番号を保持してメール本文を整理します。これはメールジャーナルだけの整理です。実体ファイルを移したり、バックアップに残る添付を消したりはしません。新しいメールファイルへ置き換える場合も `.mailfiles` は元の会員ファイル名に対応する位置へ一緒に保管してください。

## 実装の境界

メール用アダプター `mail_files` が非公開領域と参照権限を管理し、保存・SHA-256・分割転送には既存の保管庫ライブラリと転送APIを再利用します。公開保管庫の会員アダプター・ボード設定には依存しません。メール用の `MFILE...` 通信は公開保管庫の `FILE...` と分け、ZMODEMも同じメール用コネクタへ接続します。

stage63では複数添付に対応しました。メール用ZMODEMの1回の転送は1ファイルです。転送途中再開の設定・条件は `ZMODEM.md`・`ZMODEM_MENU.md`も参照してください。
