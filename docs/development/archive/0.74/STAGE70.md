# Liner notes 0.70 の変更と残件

2026年10月31日。今回の対象は、設定保存、Gather、挨拶、転送運用、DB構造、大規模運用、現行文書の整備です。既存データの移行と本番環境への適用は含みません。

## 利用者向けの変更

- エディタの行番号表示（M / /M）とPROTOCOLの選択を、PREFS SAVE/LOAD・再ログイン・切断時保存へ統合しました。設定画面のDで確認できます。通信断も保存を試みますが、プロセス異常終了・権限失効時は保証しません。本文・検索語・行カーソルは対象外です。
- Gatherの一覧継続待ちで // またはQを入力すると残りを省略して伝言入力へ進みます。GATHER READでは閲覧を終了します。/CANCELは投稿せず終了します。70 Unicode文字・10行、10行目で保存、//で確定、古い伝言から表示、保持件数の設定を維持しています。文字コードは現行UTF-8仕様です。
- 時間帯別の挨拶は、ログイン成功時に表示します。`--login-text-dir` の `greeting-00.txt` ～ `greeting-23.txt` を参照します。現在時刻に対応するファイルがなければ、前の時間帯へさかのぼり、日付をまたいで直近の非空文を選びます。すべて未配置・空なら表示しません。時刻は設定したTZに従います。配布例は06・12・18時です。1ファイルUTF-8で4,096バイトまで、再起動で反映します。誕生日の挨拶は変更していません。
- 受信後の登録処理に、ファイルごとの書込みバイト数と割合を表示します。ZMODEM通信が終わってから表示するため、ファイルのバイナリ内容に混入させません。100%は書込み量を示します。公開・登録の成功は最後の結果表示で確認してください。登録処理の高速化は今回の対象外です。
- 外部転送ヘルパーの `--timeout` は送受信・転送方式共通の無通信時間です（既定120秒、1～3,600秒）。データの入出力が続けば総所要時間が超えても継続します。権限確認だけでは延長しません。外部プロトコルの再送制限やCPU使用量制限は別です。親プロセスにはヘルパー停止時の独立した監視も残しています。

## 中断データの管理

サービス所有者または管理者が、外部管理ツールで実行します。公開ファイル・添付の本体には触れず、転送用spoolだけを対象にします。

```sh
liner-notes-admin transfers list --root /var/db/liner-notes/spool
liner-notes-admin transfers restore --root /var/db/liner-notes/spool retained-表示されたID
liner-notes-admin transfers restore --root /var/db/liner-notes/spool retained-表示されたID --apply
liner-notes-admin transfers remove --root /var/db/liner-notes/spool pending-表示されたID
liner-notes-admin transfers remove --root /var/db/liner-notes/spool pending-表示されたID --apply
```

IDはlistの`id`をそのまま指定します。restore/removeは`--apply`がなければ確認表示だけです。

- `active`: 使用中。変更不可。
- `interrupted`: 通信中断。退避済みならrestoreでZRESUMEの対象へ戻せます。同じ会員・名前空間・ボードのpendingがある場合は上書きしません。
- `publication-pending`: 受信済みで登録結果の照合が必要。削除・復帰を拒否し、BBSからZRESUMEで照合・登録を完了させます。
- `invalid`: メタデータやファイル構造が不正。自動削除せず個別確認します。

一覧には会員・保管庫/添付の区別・ボード・容量・経過時間を表示します。リンク、公開権限のあるspool項目、使用中のロックを拒否します。削除に自動的な経過日数判定は設けていません。スタンドアロン転送の旧`liner-zmodem-*`復旧領域は、現在のpending/retained管理とは別です。

## 新規構築向けのSQL保存

新しい専用データディレクトリで、初回起動時から選択してください。既存schema 1 DBや従来ファイルがある場所は、この選択では変換せず起動を拒否します。

```sh
./runtime --database-structured /path/to/new/liner.sqlite --telnet --menu 2222 /path/to/new/notes.dat /path/to/new/members.dat
```

portsのrc.conf設定は次のとおりです。サービスの作業ディレクトリは`liner_notes_data_dir`です。

```sh
liner_notes_database="/var/db/liner-notes/liner.sqlite"
liner_notes_database_mode="structured"
```

既存環境では現在の設定のまま更新できます。`blocks`が既定で、既存schema 1はそのまま使用します。既存schema 2は通常の`--database`からも読み出せます。今回、移行ツール・本番切替は追加していません。補助設定の保存後の会員データは旧0.69系では読めません。旧版へ戻す際は更新前バックアップが必要です。

schema 2では記事・メール・会員記録をそれぞれ`article_records`・`mail_records`・`member_records`へ保存します。題名・本文・ID・宛先・日時・ログイン名・パスワードのsalt/hashを個別列で管理し、これらの原本を4KiBブロックへ重複保存しません。更新はトランザクションで確定し、未確定書込みは戻します。本文の読出しキャッシュは1ストリーム1レコードです。

これはイベントを保持する行形式です。現在の会員状態だけを1行に上書きする設計ではありません。補助イベントの属性や添付ID列は`attributes`に残り、プロフィール・各種履歴などの原本は従来のストリーム形式です。DBを直接編集する用途には対応しません。全項目の完全な正規化は引き続き改善対象です。

`liner-notes-admin db-backup` / `db-export`は両schemaに対応し、1レコードずつ展開します。既存のdb-restore/db-compactは互換性を維持し、復元先はschema 1です。原本とバックアップを残す運用は変わりません。新しい補助設定も会員スナップショットへ保持します。

## 大規模運用

ストレージのSQL文を再利用し、本文読出しごとの準備処理を削減しました。メール未読件数は宛先・未読状態の索引、添付の閲覧権限は添付IDとメールの関連索引で確認します。非公開メールの宛先・送信者による制限は維持しています。

詳しい結果は配布物の`evidence/stage70/`を参照してください。試験では新規schema 2の10,050記事と10,050メールを扱い、件数に比例した本文の常駐がないことを確認しました。最大会員数・最大同時接続数での長期負荷試験とは別です。今回のFreeBSD 15.1/amd64では、常駐メモリ増加10,612,736バイト、起動と読書・追加投稿を合わせて約4.03秒でした。速度は環境に依存します。

## 残件

以下には、今回仕様確定とされた項目と、対応しないとされた項目を含めていません。

### 将来対応として保留

- COM・モデム接続。
- Web入出力。
- SSHの追加対応。既存のOpenSSH経由の入口は維持し、内蔵SSHサーバの実装は行いません。
- IPv6直接待受。
- 独自BBS間リンク・FidoNet。
- DOSドア互換。FreeBSDの外部プログラムを起動する既存ドア機能とは別です。
- 受信後の登録処理の高速化。

### 今回の初期対応から残る改善

- DBの補助イベント属性・プロフィール・履歴まで含む全項目の正規化。既存環境から新方式への移行は今回除外しました。
- 大規模運用の追加検証と改善。最大会員数・同時接続・転送を組み合わせた長時間試験、全文検索・保守処理の大容量時の性能確認。
- 中断データ管理の拡張。登録結果不明データの管理者向け照合画面、スタンドアロン転送の旧復旧領域の統合。現在はZRESUMEでの照合と、pending/retainedの明示管理です。

### RTBBSとの操作差で、今回変更を指定されていないもの

- 管理者/SIGOPの番号式の設定画面。機能は名前付きの管理コマンドで提供しています。
- 読書中のSから投稿者プロフィールへ直接進む操作。現在はPROFILEで指定します。
- 旧`#nnn`のフォーラム移動。現在はBOARD番号・ファイルボードの階層パスで移動します。
- 旧版の平面一覧・返信連鎖と、HyperNotes型の親記事一覧・返信木の違い。
- 日付入力の表記（YYYY-MM-DD）と、記事投稿者変更時の会員番号指定など、旧版と異なる入力形式。
- 全ての旧端末・外部転送ソフトの組合せとの互換性検証。個々の方式の実装と、全ての歴史的ソフトとの相互運用保証は分けて扱います。

## 今回変更しない仕様

現状で確定: 自動会員ID、プロフィール編集/検索画面、誕生日挨拶、USERLOG表示、停止行数、検索強調、行編集/範囲指定、書込み確定、メニュー案内量、トーク受信中の状態制御、チャット制限/履歴/ログ再表示、文字コード/端末制御、保存領域の一本化、設定可能な上限、無制限指定。

対応しない: ESC表示モード、回線ごとの時間帯開放、旧RTBBS保存データの直接利用・変換。以前に対象外としたDOSローカル管理画面と旧ゲートウェイも追加しません。
