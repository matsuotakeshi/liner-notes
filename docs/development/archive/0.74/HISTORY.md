### 登録方式

`--registration open|approval|closed` を指定します。省略時は従来どおり `open`。

- `open`: 登録後にログインします。
- `approval`: 登録申請とパスワードを保存し、ログインはさせません。管理者は `APPLICATIONS`（続きは `APPLICATIONS 番号`）で一覧を見て、`APPROVE 会員番号` で承認します。承認後、申請時のパスワードでログインできます。
- `closed`: 新規登録を拒否し、既存会員のログインは維持します。

初回はopenで管理者用会員を作り、その会員番号をadmins設定へ追加してから承認制へ切り替えてください。保留申請は再起動後も残り、openへ戻すだけでは承認されません。申請の却下・削除、申請理由の入力は未実装です。利用停止と承認待ちは別の状態で、承認しても利用停止は解除しません。

### 機能単位の停止

`--disable chat`、`--disable mail`、`--disable vault` を指定できます。複数ならオプションを繰り返します。省略時は有効です。

- chatは共通チャット・個別トーク・ONLINEをまとめて停止します。
- mailは送受信・下書き等のメール操作とログイン時のメール案内を停止します。
- vaultは一覧・管理操作・専用API・バイナリ転送を停止します。
- データを削除する設定ではありません。再起動して設定を戻すと再利用できます。
- 外部メニューの文言は自動で消しません。利用時に無効である旨を日英で案内します。
- 設定は起動時固定です。BBS本体やプロフィールの個別停止は未実装です。

FreeBSD rc.confでは次を使用できます。

```sh
liner_notes_registration="approval"
liner_notes_chat="YES"
liner_notes_mail="YES"
liner_notes_vault="YES"
```

各機能を止めるときは `NO` にします。従来のvaultディレクトリ・ZMODEMヘルパー設定はそのまま必要です。

## 方針

ベタ移植を目的とせず、接続ごとの状態＋単一スレッドのイベントループを採用候補とします。原版JMPCALLの16ビットスタック、KERNEL.TransferNext、PSPを再現せず、入力・出力・タイマーの待ちを明示的に扱います。各接続は1ターンに最大1コマンド、受信最大512バイトとし、バッファを固定上限にしています。

- RSDRIVER.inready/recvchar → 非ブロッキング受信＋接続別入力バッファ。
- RSDRIVER.outready/xmitchar → 接続別出力キュー＋書込み可能通知。部分送信は残量を保持。
- TIMER.waiting → 単調時計の期限。待っている接続以外は処理継続。
- KERNEL.TransferNext → pollによるイベントループと状態遷移。
- 切断 → 接続状態を破棄し、新接続へタイマー・入力を引き継がない。

これは旧Pascal APIとバイナリ互換の置換ではありません。既存の手続きを再利用する場合、待ちをまたぐローカル変数・処理段階を状態へ移す必要があります。掲示板本体をCへ翻訳するか、Pascal部分を境界API経由で残すかは未確定です。ファイルI/Oなどの長時間処理も今後の検討対象です。

## FreeBSDでの実行

```sh
make
make test
./runtime 23230
```

必要なもの: C11コンパイラ、make、試験用Python 3（外部Pythonパッケージ不要）。通常のcc/libcだけでビルドします。待受は常に127.0.0.1のみ、ポート0で空きポートをOSが選びます。最大32接続。root権限・サービス登録・ファイアウォール変更は不要です。

試験プロトコルはASCIIの行単位raw TCP。CRLF/LFを受け付けます。PING、WHO、ECHO text、WAIT 1..5000、QUITを実装。TelnetのIAC交渉、文字コード変換、旧RTBBSの画面互換は含みません。

## 受入試験

tests/test_runtime.py はサーバーを一時起動し、実ソケットを使って次を確認後、停止します。

1. Aが行を入力中でもBが応答する。
2. Aのタイマー待ち中でもBが応答し、Aは期限後に順序を保って再開する。
3. 連続したコマンドとデータが混ざらない。
4. 待ち中の切断後、新接続へ状態が漏れない。
5. 上限を超えた入力の切断が他接続に影響しない。
6. 読まない接続に負荷をかけても他接続が応答する。
7. QUITの出力を送ってから切断する。

Windows用の薄いソケット対応もあり、同じ試験をローカルで実行できます。ただしWindowsでの成功をFreeBSD実行の代用にはしません。
