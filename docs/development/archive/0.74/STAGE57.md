# Liner notes stage57 — 上限拡張・管理機能・Gather・lrzsz ports

## 変更した上限

| 項目 | stage57 |
|---|---:|
| 会員数 | 9,999 |
| 掲示板数 | 128 |
| 1入力行 | 2,048バイト（改行を除く） |
| 公開保管庫 / メール添付の累計ファイルID | 各2,000 |
| 1ファイル | 256MiB |
| 一括転送 | 16ファイル / 合計256MiB |
| 同時接続 / 同時ZMODEM子プロセス | 64 / 8 |

会員IDの権限表、プロフィール、既読、下書き、メール、転送ワーカー、チャット参加表、
Pythonコネクタ、オフライン整理ツールまで変更しています。バイナリ転送の1フレームや
Telnet制御情報の上限は入力行とは別で、従来値のままです。

記事・メール・会員別投稿数の設定値（既定0）はstage56から継続しています。
削除・整理後も記事・メール・ファイルIDは再利用しません。
**公開保管庫とメール添付の総容量は各256MiBのまま**です。予約分・途中ファイルも容量を使うため、
256MiBのファイルはその保管庫にほかの容量使用がない場合に限って登録できます。
保管庫イベント10,000件、全体8件/会員2件のアップロード予約上限は変更していません。
会員上限を増やしたため、既存の会員別下書き等の固定配列を含むメモリ使用量も増加します。

大きなファイルに十分な待ち時間を設ける場合、ヘルパー作成時に `--timeout 3600` を指定してください。
ヘルパー既定値は120秒、最大3600秒です。runtime側の転送監視も最大1時間に合わせています。
低速回線で1時間を超える転送まで保証する設定ではありません。

## 公開保管庫の物理削除・容量回収

管理者用コマンド:

```text
FILEDELETE 123 CONFIRM
```

対象IDの削除記録（イベントF）を同期保存してから実ファイルを削除し、ディレクトリも同期します。
削除済みのIDは検索・取得・再公開の対象になりません。FILEAUDITに操作者と日時が残ります。
ファイル削除の途中で失敗した場合は同じコマンドを再実行できます。IDや履歴枠の再利用はしません。
従来のFILEHIDEは非公開化だけで、FILEDELETEは復元できない物理削除です。

停止中の管理ツールでも実行できます:

```sh
./vaultctl delete /path/to/vault 123 CONFIRM
```

メール添付の回収にも同じ永続的な削除マーカーを使います。送受信者以外は、SYSOPを含め、
添付を取得できない既存の権限を維持しています。

## メールの日付指定検索・ゲストからのSYSOPメール

```text
MAIL NEWS 2026-10-30
+
MAIL NEWSFROM 123 2026-10-30
SYSOPMAIL お問い合わせ
```

MAIL NEWSは指定日のUTC 00:00以降に**自分が受信したメール**を抽出します。既読も含みます。
既読を除く通常の一覧はMAIL UNREADです。存在しない日付は拒否します。+で条件を保持して次ページへ進みます。
NEWSFROMの番号は、そこまでを読み終えたメールIDです。

SYSOPMAILはゲストでも利用でき、題名の後に通常の本文編集へ入ります。
`.` またはベタエディタの `//` で送信、/CANCELで中止。Undo・プレビュー・行編集も利用できます。
宛先はadmins設定に含まれる**有効な管理者のうち最小会員ID**です。宛先不在なら送信を拒否します。
ゲスト送信者はguestと表示され、ゲスト側から受信箱を読んだり返信を受けたりすることはできません。
この入口は添付・下書き保存に対応せず、同一接続からの連続送信には30秒の間隔を設けています。
会員は通常のMAILで宛先を選び、返信可能なメールを送れます。--disable mailはこの入口にも適用します。

## Gather伝言板

確保済みRTBBS 5.3βbソースの以下を参照しました。

- SYSTEM/CHATSYS.PAS `gather`: 保存済み伝言の古い順表示、70字×10行、//で入力終了、保持枠を超えた古い伝言の表示対象からの除外。
- SYSTEM/MAINSYS.PAS: Gコマンドは登録会員のみ、ゲスト不可。
- SYSTEM/INITBBS.PAS: 既定保持件数16、GATHER設定で変更、0で無効。

```text
GATHER
GATHER READ
HELP GATHER
```

GATHERで保持中の伝言を古い順に表示し、その後入力します。READは閲覧のみです。
1行70文字・最大10行。//で保存、先頭で//なら中止、/CANCELで全体中止、10行目で自動保存。
UTF-8ではバイト数ではなくUnicode文字数を数えます（結合文字も各コードポイントとして数えます）。
会員のログイン名・ハンドル・日時を表示します。長い一覧はEnter/+で続きを表示します。
既存メニューのGは会員登録に使われているため、その短縮キーは変更せずGATHERを追加しています。

```sh
./runtime --gather-count 16 --menu --telnet 2222 notes.dat members.dat
```

--gather-countは0～1000、既定16。0で無効です。再起動後も残ります。
表示上は最新の指定件数だけを保持し、保存元の追記ジャーナルには古い伝言も残します。
旧RTBBSの固定長ファイルそのものとの互換や、自動的な履歴消去は行いません。

## チャットログとプロフィール

公開チャットの発言は、既定で `MEMBERS_FILE.chatlog` に保存します。保存成功後に発言を配信し、
再起動後の入室時にも直近20件を表示します。個別トーク、接続者メモ、SYSOP呼び出しは保存しません。

```sh
./runtime --chat-log /path/to/public-chat.log ...
./runtime --chat-log - ...
python3 scripts/activity-export.py /path/to/members.dat.chatlog
```

`--chat-log -` は永続保存を無効にします。既定ファイルは会員ファイルが指定されている場合に作成します。
ログはチェックサム付きの専用形式で、activity-export.pyにより検証してJSON Linesへ読み出せます。
不正・途中切れのログは原本を変更せず起動を拒否します。ログの自動ローテーション・消去は行いません。
バックアップや移動はBBS停止中に実施してください。

詳細プロフィールは、従来のHANDLE/BIOに次を追加しました（各320バイト、空指定で消去）。

```text
LOCATION 地域
OCCUPATION 職業
INTERESTS 趣味・関心
WEBSITE URL
CONTACT 公開する連絡先
PROFILE ログイン名
PROFILES 検索語
```

いずれも任意入力で、ログインした会員が閲覧・検索できます。非公開連絡先の保存欄ではありません。
新旧の値はプロフィール変更ジャーナルに残ります。

## 管理者の告知・切断・停止

```text
CONNECTIONS
ANNOUNCE お知らせ本文
DISCONNECT 接続番号 CONFIRM
SHUTDOWN 300 定期メンテナンス
SHUTDOWN CANCEL
SHUTDOWN NOW CONFIRM
```

CONNECTIONSはゲストや転送中も含む全接続を表示します。DISCONNECTは接続番号1件を切断します。
同じ会員の別接続や会員の利用権限は変更せず、再接続は可能です。切断対象には管理者自身も含められます。

ANNOUNCEは接続中のメニュー利用者へ送ります。編集中の本文は変更しません。
パスワード入力中やZMODEM/バイナリ転送中は表示を待たせ、転送データへ文字列を混ぜません。
RAW接続はコネクタが利用するため告知文字列を挿入しません。オフライン会員へのメール一斉配送ではありません。

SHUTDOWNは1～86400秒後のBBSプロセス停止を予約し、途中の新規接続にも終了予定を知らせます。
CANCELで取り消せます。即時停止にはNOW CONFIRMが必要です。**FreeBSD自体の電源やOSは停止しません。**
期限になると接続と転送子プロセスを終了し、受け付け済みの保存処理・各ストアを閉じて終了します。
未送信の編集内容を自動的に下書き保存する機能ではないため、利用者は予告中に保存してください。
再起動時には停止予約を引き継ぎません。

これらの操作は管理者の実際の権限をワーカーで検証します。一般会員のメニュー/HELPには表示しません。
命令の受付記録は `BOARD_FILE.activity` に日時・操作者・対象を保存します（対象不在などの実行結果とは別）。

```sh
python3 scripts/activity-export.py /path/to/notes.dat.activity
```

rc.dにも `liner_notes_gather_count` と `liner_notes_chat_log` を追加しました。
設定例はliner_notes.rc.conf.exampleを参照してください。

## lrzsz 0.13.1 ports

`ports/comms/lrzsz/` にFreeBSD portsのディレクトリを同梱しています。
LP64環境でZCRC比較が一致せず先頭から再転送される問題に対して、do_crc_checkの反転結果を32ビットへマスクします。
BBSへlrzszのコードをリンクせず、外部プログラムとして使う構成を維持しています。
提出用差分と検証手順はports/README.mdを参照してください。PRの送信は行っていません。

ports版をLiner notesで使う場合は、実際の再開試験でその実行ファイルの検証票を作成できます。
インストール先のbinディレクトリへ追加ファイルを書き込む必要はありません。

```sh
python3 ports/test-resume.py /usr/local/bin/lrz /usr/local/bin/lsz --receipt "$PWD/lrz-resume.json"
python3 scripts/configure-zmodem.py --receiver /usr/local/bin/lrz --sender /usr/local/bin/lsz \
  --resume-receipt "$PWD/lrz-resume.json" --spool-root "$PWD/zmodem-spool57" \
  --output "$PWD/zmodem-helper57" --timeout 3600
```

runtimeには `--zmodem-helper /absolute/path/zmodem-helper57` を指定します。
既存のscripts/build-lrzsz.pyで作成したstage56以降のCRC修正版も引き続き利用できます。
ヘルパーとspoolはruntime実行ユーザーに合わせ、新しい名前で作成してください。

## 検証

FreeBSD 15.1/amd64でビルドし、通常の回帰テスト70項目を分割実行しました。
旧上限・旧プロフィール表示を期待するテストを更新し、影響部分を再実行しています。
単一のmake test実行だけが最後まで成功した、という記録ではありません。

- 9999番会員、128番ボード、2048バイト入力、64同時接続と65件目の拒否。
- 公開保管庫・メール添付の2000番、256MiB境界、物理削除後の容量回収とID非再利用。
- Gather保持枠・再起動、プロフィール検索、ゲストメールの非公開性と整理、日付検索。
- 公開チャットの再起動後の表示、一般会員の管理操作拒否、告知、切断、終了予約/取り消し。
- ZMODEM管理器の8並行枠と9件目拒否、転送中接続の切断、終了時の子プロセス回収。
- portsで作成したlrzszによる単一256MiBと16ファイル/計256MiBの実転送・全ハッシュ一致。
- Telnetメニュー、一括登録、メール添付、通信断後の途中再開、接頭部が異なる場合の再送。
- 新機能・上限テストはASan/UBSanでも成功。Windows最終ビルドでも両テストが成功。

256MiBの実転送試験は外部転送エンジン間、保管庫の256MiB登録・容量回収は別の境界試験です。
256MiBファイルのBBS経由での受信から公開までを一つの試験で通した結果ではありません。
8並行枠は転送子プロセス管理の検証であり、8本同時の最大容量転送の性能保証ではありません。

結果と初期失敗ログを `evidence/stage57/` に保存しています。採用結果の対応表は同ディレクトリの
README.md、portsのビルド・提出手順は `ports/README.md` を参照してください。
