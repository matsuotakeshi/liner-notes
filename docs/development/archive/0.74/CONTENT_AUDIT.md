# 取り消し・題名変更の操作履歴統合（第29段階）

管理者の `AUDIT` に、本人による記事取り消し（WITHDRAW）と本人・管理者による題名変更（RETITLE）を統合しました。従来の非表示・復元・会員停止・停止解除と同じ一覧で、履歴番号、UTC日時、操作者IDとログイン名、操作、記事番号、ボード番号を表示します。日英メニューと HELP ADMIN に対応します。

## 操作と閲覧権限

- メニューの `V`（小文字も可）: 最新の操作履歴。管理者以外は閲覧できません。
- `AUDIT`: 最新から表示。`AUDIT 番号`: 指定番号から過去へ表示。
- メニューの `+`: 次ページ。数字入力は履歴番号の指定です。`V`で最新へ戻り、`M`または`?`でメインメニューへ戻ります。
- 従来どおり管理者専用。記事に対する操作は、そのボードの閲覧権限が必要です。
- 1ページ最大8件、最大256件走査。ページ送りON/OFFは既存設定を使います。
- 題名の新旧値・記事本文は表示しません。取り消された内容を履歴経由で公開しないためです。
- 確認待ち・権限拒否・取り消しの再実行は履歴を増やしません。プロフィール変更は対象外です。

## 保存と過去の記録

記事変更と履歴情報は同じ `.extras` レコードに保存し、同期完了後に成功を返します。別ファイルへの履歴追記を伴わないため、記事変更だけ成功する二重書き込みはありません。今後の操作は日時と直前の管理操作連番を記録します。これにより時計の逆行に関係なく実行順が決まり、追記・再起動でもページの続きの番号は安定します。

第28段階の記録はそのまま読み込めます。ただし日時と管理操作との前後関係が記録されていないため、過去の取り消し・題名変更は「日時不明」とし、保存された順番で既存管理履歴より前に配置します。推測した日時は付けません。既存の `.extras` に対象操作がある場合、統合に伴い従来のAUDIT番号は一度変わります。移行前のページ番号は再利用せずAUDITから開き直してください。元ファイルは書き換えません。

`.extras` の512バイトレコードは維持。記事操作のbyte 1を1、byte 340–347をUTC秒（little endian uint64）、byte 348–351を直前のmoderation連番とします。チェックサム対象に含みます。旧レコードはbyte 1が0で予約領域も0です。起動時に予約領域、参照連番上限、連番の非減少などを検証します。履歴閲覧時の読み取り失敗は以後の掲示板処理を停止させます。

記事・会員・moderation・extras・ボード設定を同じ時点でバックアップしてください。新しい記録を書いたデータを旧バイナリへ戻さないでください。旧バイナリは新しいレコードを読み込めません。

## メニュー表示の追加

`MENU`でメニュー表示に切り替えます。「読む・探す」「書く・プロフィール」「会員・設定」「管理者用」「案内・終了」に分類しました。新しい `V` キーはメニュー表示時だけ有効です。本文編集中・題名入力中は従来どおり文字として扱います。履歴画面に移動案内を表示します。既存の管理者権限チェックを通るため、メニュー表示そのものが権限を与えることはありません。

メニュー追加後はWindowsで関連6系列（操作履歴統合・画面操作・多言語・ヘルプ・ページ送り・Telnet）を検証済みです。この表示変更後のFreeBSD再検証は行っていません。直前の第29段階のFreeBSD検証結果とは区別してください。
