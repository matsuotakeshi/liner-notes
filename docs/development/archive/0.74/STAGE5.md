# 複数ボード・階層・閲覧／投稿権限

2026-10-25。複数ボードの構成とアクセス制御を追加しました。設定はサーバー起動時に読み込み、会員の登録情報と突き合わせて検査します。FreeBSD 15.1-RELEASE amd64で全5試験群が成功しました。

## 試す

実機の配置先: `/home/takeshi/notes-stage5-20261025-a`。試験サーバーは停止済みです。

```sh
cd /home/takeshi/notes-stage5-20261025-a
make
./runtime 23230 notes.dat members.dat boards.example.conf
```

SSH内の別端末から `nc 127.0.0.1 23230` で接続します。サンプル設定は、公開のGeneral、その下の会員用Members・Projects、閲覧専用Announcements、初期状態では非公開のPrivateです。ボード設定を省略すると、これまでどおりID=1のGeneralのみになります。

| コマンド | 意味 |
|---|---|
| `BOARDS [続きID]` | 閲覧可能なボードを深さ優先・兄弟ID順で表示。8件ごと |
| `BOARD ID` | ボードを切り替える。成功時に現在の記事位置をクリア |
| `ACCOUNT` | ログイン中の会員の固定IDと名前を表示 |
| `NOTES` / `LIST` / `UNREAD` / `NEW` | 現在のボードだけを対象にする |
| `POST` / `REPLY` / `RESPOND` | 現在のボードに投稿する。入力開始時と確定時に権限を検査 |

記事表示や親子移動は引き続き [STAGE3.md](STAGE3.md)、会員と明示的な既読操作は [STAGE4.md](STAGE4.md) を参照してください。

接続直後・ログイン／ログアウト後の選択先はボード1です。閲覧不可なら内容取得を拒否しますが、BOARDSから他の閲覧可能なボードを選べます。切り替え失敗時は以前のボード・閲覧位置を維持します。編集中はコマンドを本文として扱うため、ボードを移るには先に/CANCELしてください。

## 設定ファイル

UTF-8、BOMなし。空行と先頭`#`の行は無視します。フィールド間に余計な空白を入れないでください。

```text
# ID|親ID|閲覧許可|投稿許可|名前
1|0|all|member|全体
2|1|member|member|会員の広場
3|2|u1,u2|u1,u2|限定会議
4|1|all|u1|お知らせ
5|1|all|none|閲覧専用
```

この例のu1/u2は、**既に登録済みの会員ID 1/2**です。まずREGISTERで会員を作り、本人がACCOUNTでIDを確認してから設定へ記載します。将来登録されるIDを先に許可する設定は拒否します。特定の会員名を先に予約して権限を渡す方式ではありません。

| 許可指定 | 意味 |
|---|---|
| `all` | 閲覧はゲストも含む全員。会員モードの投稿では、別途ログインが必要 |
| `member` | 登録してログインした会員全員 |
| `u1` / `u1,u2` | 列挙した登録済みの会員ID。最大32件 |
| `none` | 誰にも許可しない |

閲覧には、対象ボードとすべての祖先の閲覧許可が必要です。子でallを指定しても、親の制限を緩められません。閲覧不可のボードは一覧にも名前を表示しません。

投稿には、閲覧許可・対象ボード自身の投稿許可・会員モードならログインの3条件が必要です。**親の投稿許可は継承しません。** たとえば親を閲覧専用の案内にし、子には投稿できる構成が可能です。

最大64ボード、IDは1〜64。親ID=0は最上位。ボード1は必須で親ID=0とします。各ノードは記事を置けるボードであり、専用の「フォルダーだけ」の種類はまだありません。階層は最大64ノード分で、表示の字下げは深さ12まで、その先はdepthで示します。

変更を反映するにはサーバーを停止して設定を編集し、同じ記事・会員ファイルで再起動します。ライブ再読み込み、オンライン管理画面、管理者ロールや会員グループは今回未実装です。権限設定はOS側でファイルを管理できる運営者が行います。

## データ分離と保存

新規記事ファイルは`RTBOARD4`（記事1168バイト）。前段階のRTBOARD3に4バイトの所属ボードIDを追加しました。記事IDは全ボードで一意かつ不変です。ボードごとに番号を振り直さないため、番号に飛びがある場合があります。

既読ジャーナルのキーは会員IDと全体の記事IDのままで、形式変更はありません。UNREAD/NEWでは現在のボードの記事だけを調べます。別ボードの同じローカル番号という概念がないため、既読状態の衝突を避けられます。投稿・表示・返信・ツリー指定・既読変更で、現在ボードへの所属をワーカー側で検査します。ボードをまたぐ返信は拒否します。

前段階のV1〜V3はボード1のデータとして読み込めますが、ボード1以外への投稿にはV4が必要です。会員投稿には引き続きV3以上が必要です。既存形式を自動変換しません。新規試験には新しい記事ファイルを使ってください。

記事を持つボードを設定から削除すると起動を拒否します。アクセスを止める場合は行を消さずread/writeをnoneにしてください。ボードIDの別用途への再利用は行わないでください。記事移動・ボード削除・データ変換ツールは未実装です。

設定・記事・会員ジャーナルを組としてバックアップします。記事と会員ファイルの対応関係を暗号学的に結び付ける仕組みはまだなく、別環境のファイルとの取り違えを自動検出する機能はありません。

## 検証

FreeBSD実機で`make test`が成功し、前段階の全4試験群も再確認しました。

- ゲスト・一般会員・指定会員でボード一覧と入室可否が変わる。
- 閲覧制限が子へ継承され、閲覧専用・指定会員のみ投稿が働く。
- READ/TREE/REPLY/SEEN/UNSEEN/NEW/UNREADの直接ID指定で他ボードへアクセスできない。
- 各ボードの一覧・ベースノート一覧・未読に他ボードの記事が含まれない。
- 複数接続で異なるボードへ並行投稿しても所属が混ざらず、IDが重複しない。
- 再起動後も所属と既読状態を復元する。
- 重複ID・階層循環・親欠落・未登録会員ID・保存済み記事のボード欠落を拒否し、既存データを変更しない。
- 設定変更後の再起動で閲覧権限の取り消しが反映される。
