## 実機で試す

テスト環境に配置済み: `/home/takeshi/rtbbs-probe-stage2-20261025-a`。試験用サーバーは終了済み。一般ユーザーで次のように起動できます。

```sh
cd /home/takeshi/rtbbs-probe-stage2-20261025-a
make
./runtime 23230 board.dat
```

別のSSH接続で同じFreeBSDへ入り、`nc 127.0.0.1 23230` で操作します。UTF-8端末で日本語のバイト列をそのまま扱えます。Telnet交渉にはまだ対応していないため、ここではncを使用してください。待受はlocalhost固定です。

```text
POST 最初の記事
こんにちは。
2行目の本文です。
.
LIST
READ 1
REPLY 1 返信です
元の記事への返信本文です。
.
READ 2
QUIT
```

POST/REPLYには `EDIT end with . or /CANCEL`、保存完了には `SAVED 番号` が返ります。編集中の `/CANCEL` は破棄、`.` だけの行が確定。本文で先頭が`.`の行を送るには`.`を1つ追加します。編集中のQUITは本文として扱われるため、終了には先に/CANCELしてください。

- `LIST [開始番号]`: 5件ずつ表示。行は「記事番号 返信元番号 題名」。END NEXTの番号で続きを取得。
- `READ 番号`: 記事番号・返信元・題名・本文を取得。BODYの数値は本文バイト長（CRLFを含む）。本文にEND行があってもバイト長で区別可能。
- `POST 題名` / `REPLY 番号 題名`: 複数行入力を開始。
- `HELP`, `PING`, `WHO`, `QUIT`: 基本操作。第1段階のWAIT/ECHOも継続。

題名80バイト、本文1024バイト（改行を含む）、最大10000記事。制御文字は受け付けません。文字コードを変換・検証する処理は未実装で、日本語試験はUTF-8の同一バイト列保持を確認したものです。作者情報や日付の保存、認証、投稿削除・編集は今回未実装です。

## 実装と原版との関係

原版MAILSYSの「返信対象番号を保持する」意味を引き継ぎ、各記事に不変の親番号を持たせました。同じ記事への2件の返信を保存できます。原版の単一refwdを上書きする方式は採用していません。親番号を表示してREADで追える段階であり、返信木の表示やHyperNotes互換操作はまだありません。

接続スレッドが入力と出力を管理し、単一の保存ワーカーが読み書きと記事番号採番を直列化します。共有要求キューは32件、接続ごとに同時要求は1件。ファイル読み書きとfsyncの間、キューのmutexを保持しません。結果は接続スロットと世代IDを照合し、切断後に同じスロットを使った新接続へ漏らしません。

ディスク待ち中も他接続のPINGや本文入力は進められる設計です。ただし、記事の一覧・閲覧・保存は同じワーカーを使うため、ディスク待ち中の掲示板操作はキューで待ちます。低速ディスクを人工的に長時間停止したレイテンシ試験は今回未実施です。

## 保存形式と失敗時の扱い

新規の `RTBOARD1` 形式。旧RTBBSのバイナリ形式とは非互換です。構造体を直接保存せず、リトルエンディアンの固定長フィールドで記録します。

| 領域 | 長さ |
|---|---:|
| ファイル先頭のRTBOARD1 | 8バイト |
| 各記事: ID、親ID、題名長、本文長 | 4×4バイト |
| 題名領域 | 80バイト |
| 本文領域 | 1024バイト |
| FNV-1aチェックサム | 4バイト |

各記事1124バイト。FNVは破損検出用で、署名や改ざん防止機構ではありません。起動時に版・長さ・連続ID・親ID・チェックサムを検査します。POSIXはfcntl、WindowsはLockFileExで同一ファイルへの2重起動を防ぎます。POSIXの排他は協調的なので、実行中に別ツールで書き換えないでください。

投稿は追記とfsync（Windowsは_commit）が成功してからメモリへ反映し、SAVEDを返します。FreeBSDではファイル作成のディレクトリエントリもfsyncします。OSが書き込み失敗を返したら、新規投稿を停止し、成功応答を出しません。途中切れ・破損は次回起動時に原本を変更せず拒否します。復旧ツール・バックアップ世代管理は未実装です。

保存済み記事への応答が届く前に接続が切れた場合、投稿が成立している可能性があります。再送前にLIST/READで確認が必要です。編集中（確定前）の切断では保存しません。SAVED受領後のプロセス強制終了は検証しましたが、ホストの電源断・ストレージ装置の耐障害性は未検証です。

## 検証

`make test` は一時ディレクトリの新規データだけを使い、終了後に片付けます。

1. 下書き・取消の接続分離、日本語・複数行の同一内容、同一親への複数返信。
2. 存在しない親と記事、過大番号、長すぎる題名、空本文の拒否。
3. 最大8接続で16件を並行投稿し、連続かつ一意なID、一覧ページ送りを確認。
4. 同じデータを開く2番目のサーバーを拒否。
5. 再起動とSAVED後のプロセス強制終了を経ても記事・返信・次のIDが保持される。
6. 確定前に切断した下書きは保存されない。
7. チェックサム不一致、途中切れ、未知バージョンを原本変更なしで拒否。
8. FreeBSDのRLIMIT_FSIZEを128バイトに制限し、実OSによる途中書き込み失敗を発生させる。SAVEDが返らず、一覧に公開されず、他接続のPINGは成功。以後の投稿は拒否し、再起動時も不完全ファイルを変更せず拒否。
