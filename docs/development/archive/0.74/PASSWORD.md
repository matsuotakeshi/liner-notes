# パスワード変更 — 第12段階

ログイン中に `PASSWD` を入力すると、現在のパスワード、新しいパスワード、確認用の新しいパスワードの順に入力できます。日本語・英語の対話メニューとraw TCP・Telnetに対応します。各入力は8〜128バイトです。現在と同じパスワードへの変更は受け付けません。

```text
PASSWD
CURRENT PASSWORD
（現在のパスワード）
NEW PASSWORD
（新しいパスワード）
CONFIRM PASSWORD
（新しいパスワードを再入力）
PASSWORD CHANGED
```

現在のパスワードの認証は確認入力後、保存ワーカー内で行います。確認不一致、長さの不正、認証失敗では変更しません。各入力段階で `/CANCEL` を入力すると中止します。中止・失敗後は通常のコマンド入力へ戻ります。完了・中止・失敗後には1秒の再試行待ちがあります。管理者も自分の変更には現在のパスワードが必要です。stage59では、管理者が一般会員へ `RESETPASS 会員番号` で再設定できます。詳細は [STAGE59.md](STAGE59.md) を参照してください。

Telnetでは3段階ともパスワードをエコーしません。raw接続ではクライアント側で非表示入力を実装してください。エコー抑制は通信の暗号化ではなく、待受は引き続きlocalhostです。

## 変更後の接続

保存成功後、操作した接続はログイン状態と現在の記事を維持します。同じ会員の他の接続は終了し、新しいパスワードで再ログインする必要があります。下書き・タイマー・未処理の入力も破棄します。古い認証世代の保存要求はワーカーで拒否し、遅れて返った古いログイン結果で接続が復活することも防ぎます。

確認入力後に接続が切れても、既に受け付けた保存要求は完了する場合があります。成功応答を受け取れなかった場合は再接続して確認してください。記事、会員名、ボード権限、既読状態、管理者設定は変更しません。

## 保存と復旧

会員ファイルの `RTMEMB01` に128バイトのPレコードを追記します。会員IDはオフセット4、ランダム16バイトsaltは40、32バイトハッシュは56、反復回数は88、チェックサムは124です。その他の予約領域は0です。PBKDF2-HMAC-SHA256を600000回実行し、平文は保存しません。読込み時にはPレコードを順番に適用して最新の認証情報を復元します。

ディスク同期に成功してからメモリ更新と成功通知を行います。書込み・同期に失敗すると成功を通知せず、会員記録が不確定な間は掲示板操作と新規認証を停止します。既読記録など、会員ファイルの他の書込み失敗も同じ扱いです。PINGや切断は可能です。再起動時に末尾の切断・破損を検出した場合は起動を拒否し、自動修復はしません。

既存会員ファイルは変換せず使用できます。ただし、Pレコードを追加したファイルは第11段階以前のサーバーでは読み込めず、起動を拒否します。更新前と同様、停止中に記事・会員・管理記録・設定をまとめてバックアップしてください。追記方式のため過去のパスワードハッシュもファイルに残ります。履歴の圧縮・消去は未実装です。パスワード変更は `.moderation` の管理操作履歴には追加しません。

## COM・Webへの拡張

3段階の入力は共通Session、認証・保存は保存ワーカーが担当します。アダプターは `session_secret()` が真の間、入力をエコー・記録しないでください。

成功結果には `password_changed` と `account_user/account_epoch` が付きます。接続管理側は、要求元の接続IDがまだ一致し、同じ会員で終了状態でない場合に限り、その接続の認証世代を更新します。その後、同じ会員の古い接続を終了させます。通常の `session_result()` も要求元の世代を更新します。要求元が切断していても他接続への失効処理は必要です。TCPでは実装済みです。COM・Webの接続ドライバ自体は未実装です。
