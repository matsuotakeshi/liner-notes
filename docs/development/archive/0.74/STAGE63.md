# Liner notes stage63

## 今回の変更

### 接続者・回線状況

管理者メニューの `CONNECTIONS` から、接続番号、会員名、接続元IP・ポート、
TELNET/RAW、認証中・通常操作・編集中・チャット・転送中の状態、接続時間、
無入力時間、送受信バイト数、送信待ちバイト数、端末の桁数・行数を確認できます。
管理者以外にはメニューを表示せず、直接入力も拒否します。
端末サイズは取得できた値です。SSHの接続元や物理回線速度を推測して表示しません。

### メールの複数添付

1通・下書きあたり最大16ファイルです。既存の1ファイル付きメールも読み込めます。

```
MAIL SEND 相手 題名
/ATTACH 1
/ATTACH 2
/DETACH 1
/SAVE
```

`/ATTACH` は追加、同じ番号の再指定は重複登録しません。`/DETACH 番号` はそのファイルを、
`/DETACH` は全添付を外します。保存・再開・プレビュー・送信・閲覧で添付一覧を維持します。
添付の取得は送信者・受信者限定で、管理者の例外はありません。
最後の保存済み参照がなくなった添付を回収します。未送信・未保存のアップロードは自動廃棄しません。
ZMODEMのメール用アップロード・ダウンロードは従来どおり1回1ファイルです。

### 申請・会員の終了処理

| 操作 | コマンド | 実行者 |
|---|---|---|
| 申請却下 | `REJECT 会員番号 CONFIRM` | 管理者 |
| 申請削除 | `DELETEAPPLICATION 会員番号 CONFIRM` | 管理者 |
| 会員削除 | `DELETEUSER 会員番号 CONFIRM` | 管理者 |
| 自主退会 | `RETIRE CONFIRM` | 本人 |

承認待ちの申請と登録済み会員を区別します。終了した会員はログインできず、既存接続の権限も失効します。
管理者一覧に登録された会員は削除・退会を拒否します。
履歴やファイル所有者の同一性を保つため、会員番号・ログイン名は欠番として永久予約します。
記事・相手に届いたメール・取得履歴を連鎖削除する操作ではありません。会員数の累計9999枠は戻りません。
プロフィールは閲覧対象から外れます。古い認証情報・プロフィールの保存履歴を稼働用コピーから
除くには、下記の全領域整理を使います。バックアップ中の過去データは消しません。

### 保管庫・添付の上限設定

公開保管庫の `limits.conf` と、メール用 `会員ファイル名.mailfiles/limits.conf` に独立して設定します。
`vault-limits.example.conf` を雛形にしてください。設定変更後は再起動します。

| キー | 既定値 | 意味 |
|---|---:|---|
| `max_files` | 2000 | 累計ファイルIDの上限 |
| `max_events` | 10000 | 保管庫状態ジャーナルの記録数上限 |
| `max_bytes` | 268435456 | 領域のバイト数上限（受信予約も計上） |

各項目とも `0` で設定上の制限を解除できます。欠けた項目は既定値を使います。
不正なキー、重複、負数、桁あふれは設定エラーです。既存データより小さい設定へ変更しても
既存データの読み込みは可能ですが、新規登録は制限されます。
IDは削除・整理後も再利用しません。保存形式上のID上限2147483646、メモリ・ディスク容量は残ります。
1ファイル256MiB、一括転送16ファイル／256MiB、同時転送8件は今回変更していません。

### 全領域整理

`make all` で `runtime`・`vaultctl`・`memberctl` を作成します。
サービスを停止し、全データを含むバックアップから**別の新規ディレクトリ**へ整理します。

```sh
python3 scripts/maintenance.py backup \
  --root . --board notes.dat --members members.dat ../backup-stage63.tar.gz
python3 scripts/maintenance.py compact \
  ../backup-stage63.tar.gz ../notes-compacted --all-stores --tools-dir .
```

記事・メールに加え、会員の現在の認証・設定・既読・下書き、プロフィール、ボード設定・案内・
担当者、非表示／利用停止状態、記事題名・取り消し、保管庫の現在状態を整理します。
保管庫の削除・取り消しが確定した実体も整理先で回収します。
古い変更の全履歴は元バックアップに残し、整理先では現在状態に必要な記録へ集約します。
操作履歴・内部ジャーナル番号・下書きの内部改訂番号は変わる場合があります。
公開記事・メール・会員・ファイルID、記事の返信関係は変えません。

接続履歴・取得履歴・チャット・記事アクセス等のログは、従来の
`--log 相対パス --keep-log-days 日数` を併用して明示的に整理します。
累計利用時間・取得回数の集計を保持します。
カタログ・記事移動履歴は相互参照のため保持し、設定ファイル、使用中・用途不明のファイル、
未参照に見えるだけの添付、受信中のファイルを推測で削除しません。
JSONの `changes` に対象と容量差、保存した領域を列挙します。
詳細な停止・復元手順は `MAINTENANCE.md` を参照してください。

### 省メモリ化

記事・メール・会員の記事下書きは本文を常駐させず、位置・長さ等を保持して必要時に読み出します。
保管庫と添付の索引はデータに応じて伸長します。検索はディスクを順に読む方式で、全文索引はありません。
件数に比例する索引や既読情報は残ります。オフライン整理ツールのメモリ使用量は別です。
