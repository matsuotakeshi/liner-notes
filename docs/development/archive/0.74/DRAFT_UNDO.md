# 下書きの行挿入とUndo — 第19段階

本文入力中の `/INSERT 行番号 本文` で指定行の前に1行挿入できます。末尾の次の番号なら末尾に追加し、空の下書きでは1を指定します。本文を省略すると空行を挿入します。後続行の番号は1つずつ増えます。

```text
/INSERT 2 2行目の前に追加する本文
/LINES
/UNDO
```

`/UNDO` は直前の変更を1回だけ取り消します。対象は題名変更、行修正、行削除、行挿入、通常の本文追記です。戻した後にもう一度UNDOしてもそれ以前の状態には戻れません。Redoもありません。続けて編集すると、その変更の直前の状態を新しいUndo履歴として保持します。

プレビューや行番号一覧の表示、エラーになった操作、同じ題名・本文への置換は履歴を変更しません。たとえば行削除の後に不正な挿入を試しても、UNDOで行削除を戻せます。本文の16384バイト上限にはCRLF改行を含みます。空行の挿入にも2バイト必要です。エラーでは本文も履歴も変更しません。

挿入本文は文字どおり扱います。挿入する文字列がドットや編集コマンドでも、保存や編集操作として実行しません。通常の本文入力でコマンド行を書く場合は `//INSERT 1 text`、`//UNDO` のように先頭スラッシュを増やします。

## 履歴の寿命

履歴は接続内のメモリに1組だけ持ち、保存ファイルには書きません。/CANCEL、新規下書きの開始、保存要求の受付、ログアウト、切断、会員の接続失効で消去します。保存済み記事をUNDOで戻すことはできません。空本文のため保存できなかった場合や要求キューが満杯の場合は、編集を継続できるので履歴も保持します。

戻す内容は題名と本文だけです。返信先、会員、現在の記事、ボード、既読状態は変更しません。日英表示、raw、Telnet、将来のCOM・Webで共通のSession処理を使います。/LINESや/PREVIEWの画面待ち中には、先に表示を完了するかQで閉じ、本文入力に戻ってから編集コマンドを使用してください。

raw応答は挿入成功が `DRAFT LINE INSERTED`、Undo成功が `DRAFT UNDONE`、履歴がない場合が `ERR no undo` です。
