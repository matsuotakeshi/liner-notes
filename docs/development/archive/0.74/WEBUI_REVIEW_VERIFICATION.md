## 検証環境と実ファイル

- FreeBSD 15.1/amd64、Python 3.12.15。
- 専用領域 `/home/takeshi/liner-notes-web-review-20261102` のビルドと一時データを使用。
- 本番サービス、会員データ、設定は変更していない。
- WindowsのEdgeをPlaywrightから操作。SSH転送で専用のloopback WebUIへ接続。
- OBSのインストーラーは一切実行せず、転送対象としてのみ使用。

実ファイル:

```text
OBS-Studio-32.2.2-Windows-x64-Installer.exe
159809104 bytes
SHA-256 c3a0b880adbe64dc4bcb68f93016916ab5b55ae43fd227115287bf80257d92dc
```

| 試験 | 結果 |
| --- | --- |
| HTTP受信・非同期登録受付 | 0.54秒で202応答（FreeBSD内のloopback通信） |
| BBS登録完了 | 252.26秒、サイズ・SHA-256一致 |
| ダウンロード | 141.89秒、受信サイズ・SHA-256一致 |
| 他会員からの登録ジョブ照会 | 拒否 |

転送時間はこの検証環境の測定値であり、本番の回線・Apache/TLS・ストレージでの
所要時間を保証するものではない。本番での元の失敗について、詳細ログがないため
原因は断定していない。長いHTTP要求を維持する必要をなくし、再開経路とエラー表示を改善した。

同じ256,000バイトを同じコネクタで転送し、能力通知だけを切り替えて従来方式と比較:

| 方式 | 登録 | 取得 |
| --- | ---: | ---: |
| 従来の小ブロック | 36.260秒 | 19.327秒 |
| 64KiBブロック | 0.428秒 | 0.375秒 |

この小ファイル比較では登録約85倍、取得約52倍。大容量や同時転送へ同じ倍率は外挿しない。

## 更新時の注意

本体のブロック転送とWebUIを組み合わせて更新する。WebUIだけの更新では転送高速化を
利用できず、旧本体ではメール編集中の直接添付も利用できない。
本体の通常Telnet入力上限、既存データ形式、ZMODEM設定を変更する必要はない。

1. 管理者が必要なバックアップを取り、利用者へ停止を案内する。
2. 本体とWebサービスを停止し、このソースのruntimeとWebUIを配置する。
3. `webui/install.py`は既存のweb.toml、メッセージ、テンプレートを保持する。
   `web.toml.sample`の`templates`・`transfer_timeout`を必要に応じて反映する。
   未指定時も同梱テンプレートと既定120秒を使用する。
4. 独自HTMLがあれば新しい`.sample`の要素と比較して統合する。
5. 本体・WebUIを起動し、ブラウザーを再読み込みしてログインし直す。

詳細な配置・設定は[WEBUI.md](WEBUI.md)参照。今回は本番への配置・再起動を実施していない。
Apache/HTTPS経由の大容量転送、1GiB×16ファイルや同時大量転送は未検証。
