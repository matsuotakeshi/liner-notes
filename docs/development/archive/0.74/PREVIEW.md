# 投稿・返信のプレビュー — 第17段階

本文入力中に `/PREVIEW` を単独の行で入力すると、未保存の題名・本文・返信先番号・投稿者を確認できます。新規投稿の返信先は0です。確認後は本文入力に戻り、そのまま追記できます。空の本文も確認できますが、空のまま保存はできません。

| 本文入力中の操作 | 動作 |
| --- | --- |
| `/PREVIEW` | 下書きを表示し、入力に戻る |
| `.` | 記事を保存する（従来どおり） |
| `/CANCEL` | 投稿・返信の下書きを破棄 |
| `//PREVIEW` | 本文に文字どおり `/PREVIEW` の行を追加 |

プレビューは任意です。保存前の必須確認画面にはしていません。第18段階で [下書きの題名変更と行修正・削除](DRAFT_EDIT.md) に対応しました。通常行の入力では末尾へ追記します。通常のコマンド待ちで `/PREVIEW` を入力してもプレビューは開きません。本文に `/PREVIEW` と後続の文字を含む行を書いた場合は、従来どおり本文として保存します。

## ページ送りと中止

日英表示と、保存済みのPAGER設定に対応します。長いプレビューは記事と同じ画面サイズで分割します。表示途中はEnterで続き、Qまたは/CANCELで**プレビュー表示だけ**を閉じて本文入力へ戻ります。このとき下書きは残ります。本文入力に戻ってから `/CANCEL` を入力すると、下書き全体を破棄します。

表示途中のOFFまたはPAGER OFFは残りをまとめて表示し、その接続のページ送りを無効にします。プレビューの全表示を終えた場合も本文入力へ戻ります。本文入力中の通常行 `Q` や `OFF` は本文として扱います。

## 保存・権限・接続

プレビューは接続内の下書きを表示するだけで、記事番号の採番、保存、既読更新、管理記録の追加を行いません。他の接続からは見えません。現在の記事選択や一覧の続き位置も変更しません。第20段階の [/SAVEとRESUME](SAVED_DRAFT.md) で明示保存したコピーは切断後も再開できます。

投稿の権限は入力開始時と実際の保存時に保存ワーカーが確認します。プレビューを表示できたことは保存成功を保証しません。例えば確認後に返信先が非表示になった場合、保存要求は拒否されます。保存失敗後の下書きの扱いは従来仕様のままです。会員停止・認証失効時は下書きとプレビュー表示領域を破棄します。

表示は共通SessionとUIで扱い、Telnetに依存しません。rawでは以下の形で未分割の応答を返します。BODYの値は後続本文のバイト数です。通常の記事応答と区別するためPREVIEWで始め、記事IDは発行しません。

```text
PREVIEW PARENT 1 AUTHOR alice
TITLE 返信の題名
BODY 8
本文
END
```

上記は構造例です。実際のBODY値はUTF-8本文と改行のバイト数に従います。プレビュー中も入力行のUTF-8バイト列を保持し、本文の翻訳は行いません。
