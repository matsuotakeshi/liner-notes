# 第9段階: 管理者と記事の非表示・復元

会員の利用停止・解除と会員一覧は [第10段階](MEMBERS_ADMIN.md) を参照してください。

## 初期管理者の指定

管理者は登録済みの会員IDをサーバー側で指定します。最初の登録者にも自動では管理者権限を与えません。

1. 通常どおりlocalhost限定で起動し、Telnetから管理用の会員を登録します。既存会員を管理者にする場合は、その会員でログインします。
2. `ACCOUNT` または `I` で、会員名と会員IDの対応を確認します。
3. サーバーを停止し、[admins.example.conf](admins.example.conf) を参考に `admins.conf` を作ります。確認した会員IDを1行に1つ書きます。空行と先頭が `#` のコメント行を使えます。
4. 次のように起動します。

```sh
./runtime --telnet --menu --admins admins.conf 23230 notes.dat members.dat boards.example.conf
```

管理用会員でログインして `ADMIN` を入力すると「権限: 管理者」と管理コマンドを表示します。未知の会員ID、重複ID、不正な行、設定ファイルの読み取り失敗では起動を中止します。会員名ではなく数字のIDを指定してください。

`--admins` を省略するか、空の設定ファイルを指定すると管理者は0人です。既存の非表示状態はそのまま適用されます。管理者の追加・解除は設定変更後に再起動すると反映します。オンラインでの管理者付与・剥奪は今回の対象外です。

## 管理操作

| コマンド | 動作 |
| --- | --- |
| ADMIN | 自分の権限と管理操作の案内 |
| HIDE 123 | 現在のボードの記事123を非表示にする |
| RESTORE 123 | 非表示を解除し、元の記事を公開表示に戻す |
| INSPECT 123 | 管理者として元の題名・本文・投稿者を確認する |

HIDE / RESTORE / INSPECTは番号を省略すると現在の記事を対象にします。管理者でも、そのボードの閲覧権限が必要です。ボードの投稿権限とは独立しているため、閲覧できる告知用ボードの記事も管理できます。別ボードの記事は、先にそのボードを選択してください。

非表示・復元は保存ワーカーで管理者権限と現在ボードを判定してから実行します。Telnet、rawコマンド、将来のCOM・Webで同じ判定を使用できます。表示メニューの有無で権限が変わることはありません。日本語・英語の両方に対応しています。

## 非表示記事の扱い

- 通常のREAD・一覧・ツリーでは、題名・本文・投稿者を表示せず「非表示」の位置を残します。管理者も通常のREADでは同じ表示です。原文確認にはINSPECTを使います。
- 記事番号と親子関係を維持します。非表示記事を選択して親・子・兄弟へ移動でき、子記事は個別に非表示にしない限り閲覧できます。非表示は枝全体には波及しません。
- 未読一覧と次の未読から除外します。既読情報自体は変更しないので、復元後は元の既読・未読状態に戻ります。
- 非表示記事への返信と既読・未読変更は拒否します。返信を書き始めた後に対象が非表示になった場合も、保存時に再判定します。その返信は保存されません。
- 記事数・返信関係・最新番号などの構造情報は保持します。非表示は記事の存在自体を隠す機能ではありません。
- 既に読者に送信済みの本文、送信待ちになった以前の閲覧応答、端末のスクロール履歴を消去する機能ではありません。

## 保存とバックアップ

記事の元ファイルは書き換えません。`BOARD_FILE.moderation`（上記の例では `notes.dat.moderation`）に非表示・復元の変更を追記し、同期書込みが成功してから状態を反映・通知します。同じ状態への再操作では重複記録を増やしません。

記録は会員ID、記事ID、ボードID、操作後の非表示状態、時刻、連番、破損検出用チェックサムを持ちます。管理者を解除した後でも、過去の正当な変更記録は再読込できます。記録の閲覧は第11段階の [AUDIT](AUDIT.md) に対応しました。操作理由の入力、改ざん防止署名はまだありません。

**停止中に、記事ファイル・`.moderation`・会員ファイル・ボード設定・管理者設定を一緒にバックアップしてください。** `.moderation` を失うと非表示情報も失われます。初回起動時にはこのファイルを新規作成するため、復旧時に紛失した記録を空ファイルで置き換えないでください。復元操作は非表示記録の変更であり、記事ファイルの旧バックアップへの巻戻しではありません。

第8段階以前の実行ファイルは管理記録を理解せず、原文を表示します。非表示を運用し始めたデータを旧版のサーバーで公開しないでください。

書込みや同期に失敗すると、成功とは通知せず、管理状態が不確定な間は掲示板の閲覧・投稿・管理操作を停止します。通信やログアウトは可能です。再起動時は記録の切断・破損、記事・会員・ボードの不整合を検出すると起動を拒否し、元のバイト列を残します。自動修復や末尾の切り捨ては行いません。

保存形式は8バイトの `RTMOD001` と32バイト固定長レコードです。各レコードは操作種別1、非表示状態1、予約2、連番4、記事ID4、ボードID4、会員ID4、Unix時刻8、FNV-1aチェックサム4（数値はlittle endian）です。管理操作の閲覧方法は [AUDIT.md](AUDIT.md) を参照してください。
