# 管理操作履歴 — 第11段階

管理者でログインして `AUDIT` を入力すると、記事の非表示・復元、会員の利用停止・解除を新しい順に表示します。操作の連番、UTC時刻、操作者の会員IDと名前、操作種別、対象IDを確認できます。記事操作にはボードIDも表示します。日本語・英語のメニューとraw TCP・Telnetで使用できます。

## 操作

| 入力 | 動作 |
| --- | --- |
| `AUDIT` | 最新の履歴から表示 |
| `AUDIT 123` | 履歴連番123を含めて古い方向へ表示 |
| `+` | 対話メニューで次の履歴ページへ |
| `123` | 履歴画面で連番123から表示 |

指定する番号は記事番号ではなく管理履歴の連番です。存在する正の32ビット整数だけを受け付けます。履歴を見ても現在の記事選択は変更しません。表示中に新しい操作が追加されても、次ページは受け取った連番から続きます。最新の操作を取り直すには `AUDIT` を入力します。

1ページ最大8件を表示し、1要求で調べる記録も最大256件に制限しています。記事操作は、管理者でもそのボードの現在の閲覧権限がある場合だけ表示します。現在選択中のボードに限定せず、閲覧できる全ボードを対象にします。会員の停止・解除は全管理者が閲覧できます。

権限で除外した記録が多い場合、表示件数が0でも次ページが存在します。その場合は `+` で続けてください。連番とページ送り位置は全記録共通なので欠番が見える場合があります。記録数や連番の存在自体を秘匿する機能ではありません。記事の題名・本文・投稿者は履歴に表示しません。

## 保存と通信への依存

既存の `BOARD_FILE.moderation` を読みます。形式変更・変換は不要で、第9・第10段階の記録も表示できます。履歴閲覧、同じ状態への再操作、拒否された操作では記録を増やしません。ログイン、管理者設定の変更、操作理由は記録対象外です。チェックサムは破損検出用であり、改ざん防止署名ではありません。

読込みで切断・破損を検出した場合は成功として表示せず、掲示板操作と新規認証を停止します。元データの自動修復や追記は行いません。通信確認と切断は可能です。バックアップはサーバー停止中に記事・会員・管理記録・設定をまとめて取得してください。

履歴の権限判定と取得は共通の保存ワーカー、入力処理はSession、翻訳と表示はUIに置いています。将来のCOM・Webからも同じ処理を利用できます。COMドライバとWeb接続そのものは未実装です。

raw応答は次の形です。末尾の番号は次に要求する連番で、0なら終了です。

```text
AUDIT 123
EVENT 123 2026-10-26T00:00:00Z 1 alice HIDE 42 2
END NEXT 122
```

`EVENT` の並びは連番、UTC時刻、操作者ID、操作者名、操作、対象ID、ボードIDです。会員操作ではボードIDは0です。時刻が不明な記録は `unknown` を返します。
