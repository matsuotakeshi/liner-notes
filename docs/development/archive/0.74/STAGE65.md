# stage65: 操作性・管理操作・添付一括登録・DB索引・外部ゲーム

## 利用者向け

| 操作 | 内容 |
|---|---|
| `MENUMODE BEGINNER` | 通常の主画面プロンプトで全メニューを毎回表示 |
| `MENUMODE STANDARD` | 主画面メニューを接続・ログイン後に表示し、通常操作では繰り返さない（既定） |
| `MENUMODE EXPERT` | 自動メニューを省略。`MENU` / `?` で明示表示 |
| `HANDLE 表示名` | ゲストの接続中ハンドル。投稿者は `guest:表示名` として記録。会員名を偽装しない |
| `SCAN ASC ALL * *` → `F` | 選択範囲の記事を無停止で連続表示。`MAIL SCAN` → `F` はメール。入力で停止 |
| `ZMAILUPLOADBATCH 説明` | 最大16個のメール添付用ファイルを1回のZMODEMで受信 |
| `ZMAILRESUMEBATCH 説明` | 保留した同じ一括受信を再開。説明を変更せず同じファイル集合を送る |
| `MAILFILES` | 添付用に登録した番号を確認。メール編集で `/ATTACH 番号` を繰り返して添付 |
| `GAMES` / `DOOR 番号` | 許可されたFreeBSD外部ゲームの一覧・起動 |

メニュー案内量は会員ごとに即時保存します。`LOGOUT` / `QUIT`（メニューのO/Q、チャットの/QUITを含む）では言語・ページ送りON/OFF・エディタ種別・画面サイズを保存してから終了します。保存失敗時は終了せずエラーを返します。通信断・強制停止の直前の変更は保証しないため、必要なら `PREFS SAVE` を使ってください。ログイン時は保存した言語がサーバー既定言語より優先します。

無停止表示は画面ページ送りを一時的に迂回します。通常のPAGER設定は変えません。記事を自動で既読にはしません。すでに端末へ送った表示は停止キーで取り消せません。

ラインエディタのUは既存本文があると消去確認を行います。Y/空入力で消去、Nで追記した後、3秒間無入力で取り込みを終えます。投稿は別途0→Wで確定します。検索表示・件数、Undo、プレビュー、既存の入力操作は維持します。RTBBSのすべての文言やキー操作を完全に複製するものではありません。

## 管理・SIGOP

- `AUTHOR 記事番号 会員番号 CONFIRM`: 全体管理者または当該ボードを担当するSIGOP（親からの継承を含む）が投稿者を変更。変更は `AUDIT ARTICLE 番号` / 操作者別履歴にも残ります。変更後は新投稿者が本人操作を行えます。
- `BOARDGUEST ボード番号 ON|OFF`: 同じ管理範囲でゲスト投稿を許可/禁止。既定OFF。閲覧権限・ボードパスワード・投稿ACLも通過する必要があります。投稿ACLをallにするだけでは会員制運用のゲスト投稿は有効になりません。
- `MOVEBRANCH 記事番号 移動先ボード番号 CONFIRM`: 全体管理者が指定記事とその返信子孫だけを移動。指定記事を移動先の親記事にし、枝内の返信関係と記事IDは保持します。従来のMOVEはスレッド全体を移動します。
- `BOARDDELETEALL ボード番号 CASCADE CONFIRM`: 全体管理者が配下ボードを含めて削除。記事は取り消しとして残し、ボード番号・記事番号を再利用しません。ルートのボード1は対象外。途中停止時は保存済みの削除予定に基づき再起動時に処理を継続します。
- 本文の物理回収は停止後の管理ツールで `compact --reclaim-withdrawn` を使い、新しいコピーを作ります。元データとバックアップは残します。

管理者用コマンドは管理者メニュー、SIGOP用コマンドは担当者メニューに表示します。メールの私信閲覧権限は広げません。

## DB索引と保存

SQLiteの索引に記事・会員・既読・メールの情報を保持し、クリーンな終了後は原本のSHA-256一致を確認して主要索引を再利用します。本文の全文検索はFTS5、短い検索語などは従来の走査へフォールバックします。保管庫のファイル/イベント、記事操作/閲覧ログ、移動履歴、メール添付参照情報も件数に比例する常駐配列から、少数キャッシュ付きSQLiteへ移しました。

原本ジャーナルと設定用SQLiteは引き続き正式な保存領域です。単一のDBだけで全保存領域を置き換えた構成ではありません。起動時のハッシュ計算は原本全体を読み、プロファイル等の一部索引は再構築します。会員ごとの投稿数等の集計、保守処理の一時配列、順次走査も残ります。

異常終了・原本変更・ビルド変更時は索引を再構築します。保存エラー時に不完全な権限状態で運転を続けません。索引を含め、ファイルを稼働中に手動削除しないでください。`*.features.sqlite` は再生成可能な索引ではなく設定の原本です。

## 更新と互換性

停止して全データを外部バックアップしてから更新してください。記事投稿者変更(A)と返信枝移動(S)は新しい履歴種別です。一度これらを使ったデータをstage64以前で開くことはできません。戻す場合は更新前バックアップへ戻してください。既存データの書き換えや稼働中サービスの差し替えは自動で行いません。

起動・インストール・個別機能の歴史的説明はHISTORY.mdと過去のSTAGE文書へ分離しました。現行の追加仕様はこの文書、通常の操作案内は外部HELPを参照してください。
