# ボード・グループ・記事の管理

## ボードを作る・変更する

```text
BOARDINFO 番号
BOARDSET 番号|親番号|閲覧ACL|投稿ACL|題名|説明
BOARDOPTIONS 番号
BOARDOPTIONS 番号 BOARD|MENU 表示順 記事件数 本文バイト数 ログ件数
BOARDPASS 番号
BOARDPASS 番号 NONE CONFIRM
INFOEDIT 番号
SIGOP ボード番号 会員番号|NONE
BOARDGUEST ボード番号 ON|OFF
```

BOARDは記事を持つボード、MENUは振り分け専用です。長文案内はINFOEDITの共通エディタで編集します。件数・本文容量・閲覧ログ保持はボード別に設定でき、0の扱いは[設定リファレンス](configuration.md)を確認してください。全体・投稿者上限と併用されます。

`BOARDOPTIONS 番号` は種別・表示順・容量・ログ保持数と、パスワード設定のON/OFFを確認します。パスワード自体は表示しません。詳細設定・パスワード変更・長文案内の編集は、全体管理者または親から継承した権限を含む担当SIGOPが行います。記事のあるボードはMENUに変更できません。

ACLの書式は[設定例](configuration.md#board-acl)にまとめています。親の条件も適用します。ゲスト投稿ONはACLやパスワードを無視する指定ではありません。

`BOARDGUEST` は全体管理者または対象ボードの担当SIGOP（親からの継承を含む）が変更します。`SIGOP` の担当変更は全体管理者、または対象の親・祖先フォーラムのSIGOPが実行できます。対象ボードだけの担当者は、その立場だけで自分の後任を指定できません。担当が変わった会員は再ログインしてください。同じ担当者を再指定するだけなら資格の更新はありません。

`BOARDINFO` の設定詳細は、そのボードを管理できる会員だけが参照できます。`SIGOPS` は自分が管理できるボードと直接の担当会員番号を表示します。親から権限を継承しているボードでは、直接の担当がなければ会員番号は0です。一般会員の一覧は空になります。

## MMM風UIのアクセスラベル（開発版） {#mmm-access-label}

`BOARDLABEL 3 synth` で全体管理者がボード3にラベルを付けます。 `BOARDLABEL 3` で確認し、`BOARDLABEL 3 NONE` で解除します。RTBBS風・MMM風のどちらの端末UIからでも管理できます。ラベルは局内で一意です。最初の文字は英数字、以降には英数字と `.`、`_`、`-` を使えます。長さは1〜31文字で、英字の大小は同一視します。削除済みのボードに残ったラベルも `NONE` で解除できます。

利用者はMMM風UIの `open @synth`、`go @synth`、`scanlist set @synth` などで指定します。ボードACLとパスワードは既存の条件が適用されます。ラベルを変えても、会員が保存済みの巡回順は元のボード番号を参照します。

## グループ変更

`GROUPMOVE 元 先 CONFIRM` と `BOARDGROUP ボード 旧 新 CONFIRM` は、どちらも全体管理者専用です。GROUPMOVEは会員の所属を一括移行します。BOARDGROUPは指定ボードのACLにある旧グループを新グループへ置き換え、会員の所属を全体で移行し、そのボードの担当グループ記録も移します。番号は1〜100、旧と新は別の番号です。対象ボード以外のACLは書き換えないため、同じ旧グループを使う別ボードへの入室条件が満たせなくなる場合があります。移行後は他の接続が失効するため、再ログインが必要です。操作した管理者の接続は継続します。

`SIGOPGROUP ボード番号 グループ番号` は全体管理者が担当グループの記録を追加します。番号は1〜100で、対象ボード自身の閲覧・投稿ACLに含まれている必要があります。端末コマンドでは0を指定できず、0による一括解除には対応していません。重複追加は記録を増やしません。この記録だけで権限を付与するものではありません。会員を個別に追加・除外するGROUP／UNGROUPは、現在の担当SIGOP権限と対象ボード自身のACLに含まれるグループで判定し、保護会員の制限も適用します。SIGOPGROUPの記録がなくても、この条件を満たすSIGOPは操作できます。

BOARDGROUPは移行計画を保存した後、ACL・会員・担当グループ記録の順で処理します。途中停止時は再起動で未完了の計画を続行します。保存エラーが出ても変更前へ戻ったとは限りません。再実行前にバックアップとログを確認し、保存領域を復旧してください。完了済みの旧番号で再実行すると、既に対象ACLから旧番号がなくなっているため拒否されます。

## 記事とボードの整理

`AUTHOR 記事 会員番号 CONFIRM` は全体管理者・対象記事の担当SIGOPによる投稿者変更です。非表示の記事には実行できず、変更先は有効な会員（申請中・利用停止を除く）に限ります。変更履歴と投稿者ごとの件数に反映されます。`RETITLE 記事 題名` は題名変更。本人による取り消しとSIGOPの取り消しは同じWITHDRAWとして履歴へ記録します。HIDE/RESTORE/INSPECTは非表示・復元・確認で、取り消しの復元ではありません。

全体管理者は `MOVE 親記事番号 移動先ボード CONFIRM` でスレッド、`MOVEBRANCH 記事番号 移動先 CONFIRM` で枝を移動します。担当SIGOPだけでは実行できません。MOVEは現在のボードの最上位記事を指定します。MOVEBRANCHは指定記事を移動先の最上位記事にし、その子孫の返信関係を保持します。記事ID・既読状態は変わらず、非表示・取り消し記事も一緒に移動します。移動先は別の既存BOARDである必要があり、MENU・削除済みボードや、移入後に件数・本文容量の制限を超える移動先は拒否されます。

`BOARDDELETE 番号 CONFIRM` は空ボード削除、`BOARDDELETEALL 番号 CASCADE CONFIRM` は配下を含む削除です。どちらも全体管理者専用で、ルートのボード1は削除できません。空ボード削除は、取り消し済みを含む記事や子ボードが残っていれば拒否します。配下削除は記事を取り消し、対象ボードを削除済みにします。保存済み削除計画の途中で停止した場合は、再起動時に既存の回復処理で続行します。保存エラー時に処理全体が取り消されたとは限らないため、操作を繰り返す前に保存状態とログを確認してください。削除前に範囲とバックアップを確認します。

## 履歴を確認する

`BOARDACCESS 番号` は担当ボードの閲覧・投稿記録を新しい順に表示します。対象記事番号・会員番号・操作種別・日時を確認でき、記事の題名や本文は含みません。保持件数を減らしたときは保存済みログも整理されます。保持数0ではログを記録・表示しません。設定保存や整理が失敗した場合は成功扱いにせず、保存領域の状態を確認してください。

`BOARDLOG` は設定変更履歴を新しい順に表示します。現在のボードのSIGOPまたは全体管理者が利用でき、各行もその時点で管理権限のあるボードに限られます。`+` または返されたカーソルを指定した `BOARDLOG カーソル` で続きを確認します。途中で担当が解除された場合は、続きの閲覧も拒否されます。

`BOARDLOG` は設定変更、`BOARDACCESS ボード番号` は誰がいつ閲覧・投稿したか、`AUDIT ARTICLE 記事番号` は取り消し・題名・投稿者変更等の記事操作です。名前が似ていますが対象が異なります。[監査ログ](logs.md)を参照してください。

## 容量・ログ保持の意味

記事件数と本文容量の0はボード単位のquotaなし。取り消し済みを除き、非表示を含む現存記事を数えます。本文容量は題名・索引・ログを含みません。現在量より小さくしても自動削除せず、新規投稿・返信・移入を拒否します。件数の最大は2,147,483,646、本文合計は1TiBです。ディスク上の物理回収とは異なります。

閲覧・投稿ログは既定1000件、最大100000件で、**0は記録停止と既存明細除去**です（保管庫の取得履歴0=無制限とは異なります）。閲覧ログはサーバーが表示を許可した記録で、利用者が最後まで読んだ証明ではありません。記事保存後のログ保存に失敗した場合、記事番号を確認してから復旧し、同じ記事を重複投稿しないでください。

MENUへの変更は記事があるボードでは拒否され、取り消し記事も記事として残ります。順序は同じ親で小さい順、同値は番号順、ルート1は先頭。削除済みボード番号は再利用しません。スレッド移動は非表示・取り消し返信も含み、既読・IDを維持します。閲覧ログは記録時のボードに属します。

## 次期版の管理範囲と監査（未リリース）

投稿元の本人、管理者、担当SIGOP（親フォーラムからの継承を含む）はWITHDRAWで取り消せます。受信先の管理者・SIGOPによる受信記事のWITHDRAWは拒否され、HIDEで自局だけを非表示にします。表示上の投稿者をAUTHORで変更しても、受信記事の発信元は変わりません。

HIDEとWITHDRAWは、通常ボードでも共有ボードでも子孫全体を不可視にします。HIDE/RESTOREの監査記録とWITHDRAWの操作履歴は従来どおり別操作として保持します。RESTOREは直接設定したローカル非表示だけを解除し、祖先の非表示や投稿元の取り消しを打ち消しません。INSPECTは閲覧権限と担当管理権限を持つ利用者だけが実行できます。不可視の子孫の確認は可能ですが、取り消された記事自身の本文はINSPECTでも表示しません。物理回収は[外部管理ツール](backup-recovery.md)で別途実行します。
