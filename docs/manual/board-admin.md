# ボード・グループ・記事の管理

## ボードを作る・変更する

```text
BOARDINFO 番号
BOARDSET 番号|親番号|閲覧ACL|投稿ACL|題名|説明
BOARDOPTIONS 番号 BOARD|MENU 表示順 記事件数 本文バイト数 ログ件数
BOARDPASS 番号
BOARDPASS 番号 NONE CONFIRM
INFOEDIT 番号
SIGOP ボード番号 会員番号|NONE
BOARDGUEST ボード番号 ON|OFF
```

BOARDは記事を持つボード、MENUは振り分け専用です。長文案内はINFOEDITの共通エディタで編集します。件数・本文容量・閲覧ログ保持はボード別に設定でき、0の扱いは[設定リファレンス](configuration.md)を確認してください。全体・投稿者上限と併用されます。

ACLの書式は[設定例](configuration.md#board-acl)にまとめています。親の条件も適用します。ゲスト投稿ONはACLやパスワードを無視する指定ではありません。

## グループ変更

`GROUPMOVE 元 先 CONFIRM` は所属会員の一括移行です。`BOARDGROUP ボード 旧 新 CONFIRM` は対象ボードのACL変更と所属移行をまとめます。担当SIGOPが扱える範囲と保護会員の制限を検査します。別ボードにも使っているグループを移す際は、その影響を先に確認してください。

## 記事とボードの整理

`AUTHOR 記事 会員番号 CONFIRM` は投稿者変更、`RETITLE 記事 題名` は題名変更。本人による取り消しとSIGOPの取り消しは同じWITHDRAWとして履歴へ記録します。HIDE/RESTORE/INSPECTは非表示・復元・確認で、取り消しの復元ではありません。

全体管理者は `MOVE 親記事番号 移動先ボード CONFIRM` でスレッド、`MOVEBRANCH 記事番号 移動先 CONFIRM` で枝を移動します。元・先の権限、返信関係、既読・履歴の対応を保持します。

`BOARDDELETE 番号 CONFIRM` は空ボード削除、`BOARDDELETEALL 番号 CASCADE CONFIRM` は配下を含む削除です。ルートのボード1は削除できません。削除前に範囲とバックアップを確認します。

## 履歴を確認する

`BOARDLOG` は設定変更、`BOARDACCESS ボード番号` は誰がいつ閲覧・投稿したか、`AUDIT ARTICLE 記事番号` は取り消し・題名・投稿者変更等の記事操作です。名前が似ていますが対象が異なります。[監査ログ](logs.md)を参照してください。

## 容量・ログ保持の意味

記事件数と本文容量の0はボード単位のquotaなし。取り消し済みを除き、非表示を含む現存記事を数えます。本文容量は題名・索引・ログを含みません。現在量より小さくしても自動削除せず、新規投稿・返信・移入を拒否します。件数の最大は2,147,483,646、本文合計は1TiBです。ディスク上の物理回収とは異なります。

閲覧・投稿ログは既定1000件、最大100000件で、**0は記録停止と既存明細除去**です（保管庫の取得履歴0=無制限とは異なります）。閲覧ログはサーバーが表示を許可した記録で、利用者が最後まで読んだ証明ではありません。記事保存後のログ保存に失敗した場合、記事番号を確認してから復旧し、同じ記事を重複投稿しないでください。

MENUへの変更は記事があるボードでは拒否され、取り消し記事も記事として残ります。順序は同じ親で小さい順、同値は番号順、ルート1は先頭。削除済みボード番号は再利用しません。スレッド移動は非表示・取り消し返信も含み、既読・IDを維持します。閲覧ログは記録時のボードに属します。

## 次期版の管理範囲と監査（未リリース）

投稿元の本人、管理者、担当SIGOP（親フォーラムからの継承を含む）はWITHDRAWで取り消せます。受信先の管理者・SIGOPによる受信記事のWITHDRAWは拒否され、HIDEで自局だけを非表示にします。表示上の投稿者をAUTHORで変更しても、受信記事の発信元は変わりません。

HIDEとWITHDRAWは、通常ボードでも共有ボードでも子孫全体を不可視にします。HIDE/RESTOREの監査記録とWITHDRAWの操作履歴は従来どおり別操作として保持します。RESTOREは直接設定したローカル非表示だけを解除し、祖先の非表示や投稿元の取り消しを打ち消しません。INSPECTは閲覧権限と担当管理権限を持つ利用者だけが実行できます。不可視の子孫の確認は可能ですが、取り消された記事自身の本文はINSPECTでも表示しません。物理回収は[外部管理ツール](backup-recovery.md)で別途実行します。
