# DB構造と保存方式

## 正式保存と索引

`--database` を指定したSQLiteが正式保存先です。WALと確定処理を使い、成功応答より前に書き込みを確定します。排他ロックにより同じ保存領域への競合起動や保守を拒否します。保存先を指定しない旧Liner Notesファイル運用とは区別します。

新規に `--database-structured` または `database_mode=structured` を選ぶとschema 5を作ります。通常の `--database` は既存schema 1～5をそのまま読み、自動変換しません。空でない旧保存領域へ新規構築用フラグを付けるだけでは移行できません。

| 形式 | 主な内容 |
|---|---|
| schema 1 / blocks | 論理ストリームをブロックとして保存 |
| schema 2 | 記事・メール・会員の主要レコードを項目別テーブル化 |
| schema 3 | プロフィール、活動・閲覧・取得・接続・チャット・Gather、ボード・SIGOP・移動・記事操作等も項目別保存 |

`article_records`、`mail_records`、`member_records` 等にID、日時、題名、本文、宛先、ログイン名、認証用salt/hash等を保存します。イベント履歴を保持する形式で、現在状態だけを1行で上書きするモデルではありません。補助属性・添付ID群・対応外ストリーム等は属性列またはblocksに残ります。ファイル本体はDB外です。

## 大規模運用上の性質

本文全体を常駐させず、SQLの索引・全文検索と必要時の読み出しを使います。一方、件数に比例する索引・既読情報、起動検査・保守・一部集計や巡回処理は残ります。SQLiteを使うことだけで最大会員数・同時転送数の処理時間を保証しません。

`*.features.sqlite` は設定の原本を含むため、単なる再構築可能キャッシュと考えて削除しません。BBS本体、Webの再開記録、リンクDBと秘密鍵、ゲームDBは別の保存領域です。

## バックアップ・変換

structured形式は `db-backup` の形式情報に記録され、`db-restore` / `db-compact` も保持します。形式情報がない古いバックアップは既定でblocksへ復元し、明示的な `--structured` で新しいコピーへ変換できます。`db-structure` は停止中の原本を変更せず別コピーへ変換し、全ストリームのSHA-256を照合します。

SQLを直接編集する運用には対応しません。業務検査・履歴・権限を通すBBSと[管理ツール](backup-recovery.md)を使用してください。稼働中SQLiteの単体ファイルコピーだけではWALを含めた整合バックアップになりません。

## schema 5の項目別保存

0.75の新規structured DBはschema 5となり、メール添付は順序付きの `mail_attachments`、会員グループは
`member_event_groups` へ保存します。会員の設定・削除・既読・下書き・パスワード変更の
補助項目も専用の列に分けます。保管庫とメール添付保管領域のメタデータは
`vault_records` へ保存し、それぞれのファイル番号を混同しません。本文・ファイル本体、
履歴の意味、会員番号・記事番号は変更しません。

既存schema 1/2/3/4/5は自動変換せず、それぞれの形式で読み書きします。
停止中の原本とバックアップを保持し、`db-structure` で別コピーを作成してください。
全ストリームのSHA-256、SQLite整合性・外部キー・項目間の関連を照合してから、WALを
反映し、完成DBのファイル名を確定します。失敗したコピーを起動してはいけません。
新しい管理ツールによるstructuredバックアップの復元先もschema 5になります。
旧実行ファイルへ戻す際は元のDBも一緒に戻し、schema番号だけを書き換えないでください。

現在の標準ストリームは項目別保存ですが、歴史的なRTBOARD1/2/3形式や未知の拡張
ストリームは、内容を壊さないためblocksのまま保持します。変換結果の
`typed_streams` と `compatibility_streams` で確認できます。既知形式の解釈できない
補助バイトは黙って削除せず変換を拒否します。元のデータを保存して調査してください。

リンク・WebUI・Doorの独立DB、SSHの鍵設定、再構築可能な索引、ファイル本体は
役割・所有者が異なり、BBS本体DBへ統合しません。必要な保存領域を含めて
[バックアップと復元](backup-recovery.md)の停止・保管手順を守ってください。
