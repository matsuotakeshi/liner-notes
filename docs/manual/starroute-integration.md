# StarRoute Tradersとの連携

StarRoute Tradersは別配布のゲームです。Liner Notes本体はゲーム固有のAPIを持たず、既存のPTY、認証済み会員ID、登録済み実行ファイルを使います。StarRouteの新規宇宙作成・パッケージ更新・共有マスター設定は、**実際に導入するStarRouteの版のマニュアル**に従ってください。古い単独導入キットの初期化手順を既存宇宙へ適用しません。

## 既存ゲームを登録する

実行ラッパーと保存先を確認し、既存doors.confの他ゲーム行を保持して次の形式で指定します。

```text
1|0|3600|/usr/local/libexec/starroute-door|/var/db/starroute-traders|StarRoute Traders
```

番号・最低レベル・時間制限・実行パス・作業ディレクトリ・表示名です。上記パスは例なので実際の配置へ合わせます。既存の6項目設定は変更不要で、DORINFO1.DEFを追加する必要もありません。ラッパーが利用するPython・ゲームコード・設定がBBSの限定された環境から参照可能であることを確認します。

認証済みの `LINER_USER_ID` と `LINER_USER` を利用し、複数BBSの世界での識別はStarRoute側のBBS識別設定と組み合わせます。BBSの会員名入力を任意のシェル命令に展開しません。

## 端末と復帰

GAME→番号で起動し、ゲーム内quitでゲーム一覧へ戻ります。`DOOR 1` の直接起動は元のBBS画面へ戻ります。TelnetのNAWS変更はPTYへ伝わりますが、ゲーム側も `os.get_terminal_size()` 等で現在サイズを取得する必要があります。COLUMNS/LINESは起動時だけです。

## 更新・確認・復旧

1. BBS・ゲームの実行パス、doors.conf、ゲーム設定・保存先を記録する。
2. ゲーム利用者と日次保守を止め、設定・世界データ・旧プログラムを保存する。
3. 新しい組合せを別データ・別ポートで確認する。
4. 日本語・英語、会員識別、80×24→100×30、移動・売買、quit、再入場を確認する。
5. 本番の起動先を切り替えて、既存The Clans等も起動確認する。

Liner Notesの更新で宇宙をinit/resetする必要はありません。既存世界のルール変更や移行はゲーム側の手順に従います。不調時は保存済みの旧プログラム・設定の組へ戻し、更新後のゲーム進行も別に保存してからデータ復元を判断します。

このマニュアルは特定のStarRoute最新バージョンを指定しません。旧導入記録だけから現行ゲームの設定キーや移行互換を推測しないためです。[汎用Doorの権限・排他・異常終了](external-games.md)も確認してください。
