# 運用・監視・告知・停止

## 起動状態を確認する

次期版の`liner-notes-doctor --check-all`で設定・DB・権限・外部機能を読み取り専用で診断できます。終了コードと対象範囲は[設定診断](troubleshooting.md)を参照してください。停止や自動修正は行いません。

FreeBSDは `service liner_notes status` と `sockstat -4l -P tcp`、Linuxは `systemctl status liner-notes`、`ss -ltnp`、`journalctl -u liner-notes` を使います。Web・リンクは別サービスです。監督プロセスが存在するだけで本体が待受中とは限りません。変更後は実際のログインまで確認します。

rc.confの `liner_notes_program` が標準以外を指している場合、パッケージの更新だけでは起動中プログラムは切り替わりません。実行ファイルの存在と設定優先順位を確認します。Linuxで古いunitが別ディレクトリから優先される場合も同様です。

## BBS内の接続管理

`CONNECTIONS` はゲスト、通常操作、転送、Doorを含む現在接続を表示し、通信量・無入力時間・接続元・状態を確認できます。`DISCONNECT 接続番号 CONFIRM` は指定接続を切断します。対象を現在の一覧で確認してください。

`ANNOUNCE 本文` は接続中のメニュー利用者へ告知。`SHUTDOWN 秒数 理由` は1〜86400秒の終了予告、`SHUTDOWN CANCEL` は解除、`SHUTDOWN NOW CONFIRM` は即時停止です。外部監督が自動再起動する構成では、長時間停止したい場合にOS側でもサービスを止めます。

## 無入力・接続時間

通常操作には無入力時間制限、会員レベル別には接続時間と警告・猶予を設定できます。**admins.confで指定した全体管理者は、この利用時間・無入力制限の対象外**です。会員レベル5やSIGOPだけでは免除されません。外部転送・COMの無通信タイムアウトは独立して適用されます。

## 日常確認

- DB・保管庫・添付・Web spool・転送spoolとバックアップ先の空き容量を確認する。
- 起動・接続・権限・転送失敗のログを確認し、秘密入力や私信本文を診断ログへ追加しない。
- 更新前に新しいパッケージを構築し、停止・バックアップ後に配置する。
- 復元コピーでログイン、記事、メール、添付、保管庫、ゲーム、権限を定期確認する。
- 共有リンクの待ち件数・容量・証明書期限と、相手との同期状態を確認する。

全機能の入口があることと、全端末・ブラウザー・最大容量の組合せを確認済みであることは別です。物理モデム、設置先のHTTPS経路、最大規模の長期運転、外部ゲームは個別の受入確認が必要です。テスト結果の詳細は開発リポジトリに保管し、運用手順とは分けています。

SolarisでDoorを設定した場合、`liner-notes-doctor --check-doors`は小さい排他helperの配置・所有者・mode・実行権と親ディレクトリを検査します。helper自体は起動せず、Door未使用時には必須扱いしません。詳しくは[Solarisの導入](install-solaris.md)を参照してください。
