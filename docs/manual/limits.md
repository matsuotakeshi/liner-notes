# システム上限と無制限指定

## 実行時上限

`limits.conf` は以下の上限を**縮小**するための設定です。正の値を指定し、実装上限を超える値と0は拒否します。値の変更は本体再起動で反映します。

| キー | 既定値・実装上限 |
|---|---:|
| members | 累計999,999会員 |
| boards | 1,024ボード |
| input_bytes | 4,096バイト/入力行 |
| body_bytes | 262,144バイト（256KiB）/記事・メール本文 |
| file_bytes | 1,073,741,824バイト（1GiB）/ファイル |
| batch_files | 16ファイル/一括 |
| batch_bytes | 17,179,869,184バイト（16GiB）/一括 |
| connections | 128接続 |
| transfers | 24同時転送 |

UTF-8のバイト数であり、日本語の文字数ではありません。Web・Apache・外部転送・保存先の空き容量に、より小さい制限がある場合はそれも適用されます。

## 保存件数・容量のquota

記事・メール・投稿者単位の件数制限は別の起動設定で、0はそのquotaを無制限にします。保管庫と非公開添付のlimitsは各領域に適用します。

記事・メールの件数は累計です。取り消し・削除・本文回収をしても、そのIDを再利用したり、累計の採番枠を戻したりはしません。保存容量の回収と、累計件数の制限解除を混同しないでください。

| vault-limits.conf | 配布既定値 | 0 |
|---|---:|---|
| max_files | 累計2,000ファイル | 件数quota無効 |
| max_events | 10,000イベント | イベントquota無効 |
| max_bytes | 17,179,869,184バイト（16GiB） | 容量quota無効 |

既存運用の設定ファイルが小さい場合は更新しても自動で上書きしません。quota無効はIDや整数の上限、ディスク容量がなくなる意味ではありません。記事・メール・会員・ファイルの業務IDは整理後も再利用せず、ファイルIDには2,147,483,646の表現上限があります。

## その他の制限

会員レベル0〜5、グループ1〜100、メール添付1通16件。プロフィールの1行自己紹介は320バイト、長文は8192バイト、ハンドルは80バイト。Gatherは70文字×10行、チャットは512バイト/発言。Door設定32件、同時枠はゲームごとに1〜32です。

Web max_sessionsの配布例は64で、本体接続枠とは独立です。補助端末を開くと追加接続を使用します。上限までの設定が可能なことと、その最大組合せでの長期運用を検証済みであることは別です。
