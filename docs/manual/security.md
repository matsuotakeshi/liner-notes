# セキュリティと権限モデル

本体は専用の非rootアカウントで動かします。管理者会員はOSのrootではありません。DoorはBBSと同じOSユーザーで動くため、信頼できるプログラムだけを登録し、root runtimeからの起動は拒否します。PTYはゲームのOS隔離機構ではありません。

Telnetは平文です。インターネットからの利用にはHTTPS WebUIまたは適切に管理したSSH経路も検討します。低番号ポートを使うためだけに本体をrootで常駐させず、[ポート23の権限](connections.md)を設定します。

会員認証、管理者・SIGOP、レベル・グループ、親ボードACL、共通パスワード、本人所有、メール送受信者を各操作で確認します。Web画面の非表示だけに依存しません。パスワード・会員データ・秘密鍵をWeb公開ディレクトリへ置かないでください。

Webアカウントは私有spoolと設定を必要範囲で読み書きしますが、BBS原本を直接読みません。Cookie/CSRF/Originを検査し、任意のOSコマンド・SQL実行画面はありません。Webリンク管理は限定されたローカルソケットで、秘密鍵・DBへの読取権を与えません。

共有リンクは接続相手と発信元を別に登録し、公開鍵の指紋を別経路で照合します。会員・私信・保管庫は共有しません。識別鍵を失うと同じBBSとして復旧できなくなるため、専用DBと合わせて保存します。

バックアップは会員・私信・認証情報を含み、暗号化ファイルではありません。所有者だけが読める場所へ保存し、第三者提供や公開ZIPへ混入させません。手順の設定例に実際のパスワード・秘密鍵を書き込まないでください。

SELinuxが有効な環境で動作することと、専用の制約ドメインを提供することは異なります。0.74.1 RPMは専用SELinuxポリシーを提供しません。拒否をSELinux無効化で回避せず、ラベル・サービス権限・パスと拒否ログを確認します。

## 任意のSELinuxポリシー

`linux/selinux/` にRocky Linux 10向けの任意導入パッケージ
`liner-notes-selinux` を用意しています。既存の本体・Web・リンクの3 RPMとは別です。
コンパイル成功とEnforcingでの機能・拒否試験は異なるため、後者の確認完了までは
本番向けの全機能対応として扱いません。

|対象|専用ドメイン|主な保存領域|
|---|---|---|
|BBS|`liner_notes_t`|`/var/lib/liner-notes`|
|WebUI|`liner_notes_web_t`|`/var/lib/liner-notes-web`|
|リンク|`liner_notes_link_t`|`/var/lib/liner-notes-link`|
|管理コマンド|`liner_notes_admin_t`|オフライン管理対象|
|Door|`liner_notes_door_t`|`/var/lib/liner-notes-doors`|
|転送helper|`liner_notes_transfer_t`|`/var/lib/liner-notes/spool`|

オフライン管理用の保存先 `/var/backups/liner-notes` は `liner_notes_backup_t` です。
管理者が適切なUnix所有者・権限で作成してから明示的にラベルを設定します。
通常のデーモンはこの保存先を読みません。復元したコピーを運用データとして使う際は、
停止中に配置先・所有者を確認し、BBS用のラベルへ復旧してから起動します。

WebUIからBBS原本やリンク秘密鍵への直接アクセス、DoorからBBS原本へのアクセスは許可しません。
転送helperは既存の認証済みRPC用FDを使用します。Doorへの切替には管理者が設定した
`liner_notes_door_exec_t` の実行ファイルが必要です。任意の外部ゲームを無条件に許可する仕様ではありません。
Doorの外向き通信は既定で無効です。必要な場合だけ `liner_notes_door_network` と接続先ポートを検討します。

ポリシーRPMは優先度200で導入し、優先度400のローカルポリシーを置き換えません。
導入・更新ではサービスを再起動せず、データや設定を再ラベルせず、ポート定義も変更しません。
稼働中の専用ドメインがある場合は削除を拒否します。削除時も管理者の
`semanage fcontext` / `semanage port` の設定と保存データを消しません。

`liner-notes-selinux` は既定で現在のモードとモジュール登録を表示するだけです。
明示的な `liner-notes-selinux --relabel` はroot専用で、標準配置の存在するパスだけに
`restorecon -R` を実行します。ローカルなfcontext定義を尊重し、`-F` は使用しません。
独自配置は管理者が対象パスと適切な型を確認して登録してください。ポートの既存割当は
`semanage port -l` で確認し、他のサービス用の型を機械的に変更しないでください。

### Enforcing受入CIの準備（検証機専用）

内蔵SSHは任意機能です。ポリシー0.3.0では、専用ディレクトリ
`/etc/liner-notes/ssh-host-keys/` を `liner_notes_ssh_secret_t`、専用待受を
`liner_notes_ssh_port_t` として扱います。鍵の読み取りはBBSとオフライン管理者に限定し、
書き換え権限は与えません。Web・リンク・Door・Brokerなどへ読み取りを許可しません。
インストール時に既存sshdの鍵やポート22を変更する処理はありません。
鍵は所有者・0600権限を保ち、設定のバックアップへ別途含めてください。
同一UIDの従来型Doorを安全に隔離する機能とは別で、Broker有効時の別UID起動が必要です。
実接続と拒否をEnforcing上で検査するまで、SSHのSELinux対応完了とは扱いません。

`Rocky SELinux policy` のPRジョブはポリシーのコンパイル、許可ルール、RPMの導入・
更新・削除とローカルラベル保持を検査します。mainジョブは既存CI専用鍵でRocky検証機へ
接続し、Telnet、記事、メール、SQLite再起動、Web、署名付きリンク、Door、実ZMODEMと
管理コマンドを専用ドメインで試験します。Web・Door・転送から原本を読めないことは、
同じUnix所有者のファイルを用いてMAC拒否として確認します。
リンク試験では双方から相互TLSでpullを行い、署名付き記事の受信とBBS記事の外部への送信をそれぞれ確認します。
同じZMODEM送受信手順をhosted CIでも実BBS・実lrzszで確認します。これは転送手順の回帰検査であり、専用ドメインとMAC拒否はEnforcing実機で別途確認します。
転送ドメインは、BBSから継承したRPCソケットの型・プロトコル参照（`getopt`）を許可します。BBSソケットへの新規接続（`connectto`）やオプション変更（`setopt`）は許可せず、コンパイル済みポリシーでも確認します。
管理ドメインで論理バックアップ・内容検証・別コピーへの復元を実行し、復元したコピーの
ラベルをBBS用に設定したうえで記事とメールを再度読み出します。
SQLを正本とする保管庫の管理試験では、停止済みデータを管理ドメイン内で私有の作業コピーへ複製し、`db-export`で別コピーへ索引を展開してから`vaultctl list`を実行します。SQLiteの読み取り専用接続でもWAL/SHMが作成され得るため、SQL操作は作業コピー内に限定します。元の`index.dat`をSQLの最新状態と誤認しないようにし、同じ複製・書き出し・一覧・バックアップ・復元手順をhosted CIでも検査します。hosted試験は原本ファイルの不変性を確認しますが、SELinuxの専用ドメインでの成功を意味しません。

運用時はSELinuxをEnforcingのまま、管理者がjournalと監査ログを確認します。
拒否された操作・サービスの実行ドメイン・対象ファイルやポートの型を照合します。
個別のAVC拒否から機械的に許可ルールを追加せず、インストール時のラベルと設定を先に確認します。
セットアップは[Linux導入](install-linux.md)を参照してください。

配布元のlrzszがない場合や必要な転送試験に失敗する場合は、[Linux導入](install-linux.md)の
隔離ビルド手順で用意した実エンジンを使います。版名だけで転送成功を判断しません。
0.75と同じソースSHAのRocky Linux 10検証機で、専用ポリシーをEnforcingのまま検証しました。
これとは別に、使い捨てRocky Linux 10環境でポリシーRPMの導入・リビジョン更新・削除を確認しました。
[実機CI](https://github.com/matsuotakeshi/liner-notes/actions/runs/45773929619) ·
[版・SHA・配布物の照合](https://github.com/matsuotakeshi/liner-notes/actions/runs/45775262020)


### 認証付きDoorの追加ポリシー

Broker、特権起動サービス、ゲームサーバー用consumerを別ドメインとする追加ポリシーを開発中です。
BBS・ゲームクライアントからBrokerへの直接接続、ゲームから起動サービスへの接続、各追加サービスからBBSデータへのアクセスは許可しません。
起動ラッパー・設定・実行枠の所有者も確認し、SELinuxだけに権限判定を任せません。
起動サービスは専用UIDの使用中判定のためにプロセス状態を読み取ります。対象が消滅した競合と、
権限拒否・確認不能は区別し、後者では実行枠を再利用しません。systemdから継承済みのjournal接続には
読み書き・属性取得を許可しますが、systemdへの新規接続や汎用daemon属性は追加しません。
ログ書き込みが成功しても、起動時に出力先がnullへ差し替えられている場合があります。
診断では固定メッセージが実際のjournalに届くことまで確認してください。
追加のラベル復旧は明示操作とし、既存のローカルラベル設定を保持します。
ポリシーRPMの生成・許可表検査と、実際のEnforcing下でのサービス動作は別検証です。
この追加分の実機成功が確認されるまでは、本番への有効化手順として扱わないでください。

## 任意のDebian AppArmorポリシー

開発中の `liner-notes-apparmor` はDebian 13 amd64の標準DEB配置が対象です。
Debian 12・Ubuntu・ソースインストール版の動作は未検証です。

SELinuxは主にラベル、AppArmorは主にファイルのパスとプロセスのプロファイルで制約します。
どちらもサービス専用ユーザー、Unix権限、systemdの既存制約、BBSの認証・ACLと併用します。
AppArmorがカーネルで有効でも、対象プロセスにプロファイルが付いているかは別に確認します。
Enforceではポリシーが違反操作を拒否します。Complainでは通常の許可ルールの不足はログ記録にとどまり、明示的な拒否は適用されます。

| プロファイル | 主な範囲 |
| --- | --- |
| `liner-notes` | 本体データ・ログ・専用SSH鍵、Telnet／内蔵SSH、転送・隔離コネクタ |
| `liner-notes-web` | Web専用設定・spool、BBSプロトコル、リンク管理ソケット |
| `liner-notes-link` | 専用DB・ノード鍵・TLS・リンク会員の認証ファイル |
| `liner-notes-transfer` | 継承した転送RPC、spool、明示した転送プログラム |
| `liner-notes-admin` | 明示起動するオフライン管理と専用バックアップ先 |
| `liner-notes-door-broker` | Broker専用設定とUnixソケット |
| `liner-notes-door-launcher` | 別UID起動、PTY、実行枠とBroker接続 |
| `liner-notes-door` | 管理者が承認した1ゲーム分のプロファイル例 |

Web・リンク・DoorにBBS原本への直接アクセスを許可していません。転送は本体から
別プロファイルへ必ず遷移します。Doorは別UIDの隔離経路を前提とし、登録済みの
実行ファイルごとに管理者が遷移を明示します。認証consumerは外部アプリケーション側の
専用ポリシーと受入試験が必要です。

カーネルによるネットワーク・Unixソケットの制約は機能セットに依存します。
Door起動用の有効化例ではsystemdでもソケットファミリーをAF_UNIXに限定します。
接続先・ソケット利用者は、運用上のファイアウォール、Unix権限とアプリケーション側の確認を併用します。
導入は[Linuxの導入](install-linux.md)、独自配置は[設定](configuration.md)を参照してください。
